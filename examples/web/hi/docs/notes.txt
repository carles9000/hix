Encontrado. El WebSocket detrás de Cloudflare falla por el detector de protocolo, y es un fallo que localhost nunca
  reproduce.

  Cómo enruta HIX una conexión WS sin SSL (hix_server.prg:670):

  harbour
  cPeek := HIX_SocketPeek( hConn, nPeekBytes, nPeekMs )   // 512 bytes, 10 ms
  cTipo := iif( cPeek != NIL, HIX_DetectProtocol( cPeek ), HIX_CONN_HTTP )

  HIX_DetectProtocol (hix_socket.prg:74) busca literalmente "upgrade: websocket" dentro de ese peek. Si no lo ve, la
  conexión cae a HIX_CONN_HTTP — y el worker HTTP solo hace upgrade si la conexión es SSL:

  harbour
  IF oIO:lUseSSL .AND. Lower( oReq:Header( "upgrade" ) ) == "websocket"   // hix_worker_http.prg:100

  Resultado: el cliente nunca recibe el 101 Switching Protocols, y el navegador reporta close code 1006 — exactamente tu
  síntoma, y en 192 ms (rechazo inmediato, no timeout).

  Dos razones por las que el peek falla tras Cloudflare y no en local:

  1. peek_timeout_ms: 10 — hb_socketRecv(..., MSG_PEEK, 10) espera 10 ms a que haya bytes. En loopback los datos ya
  están ahí; desde internet, entre que Cloudflare abre el socket al origen y manda el request pasan fácilmente más de 10
  ms. nRead <= 0 → NIL → HTTP por defecto.
  2. peek_bytes: 512 — Cloudflare añade CF-Ray, CF-Connecting-IP, CF-Visitor, CDN-Loop, X-Forwarded-For,
  X-Forwarded-Proto… Si Upgrade: queda fuera de los primeros 512 bytes, o si el request llega fragmentado en varios
  segmentos TCP, el token no aparece en el peek.
