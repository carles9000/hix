# HIX v2.3.00

**Date:** 2026-09-29
**Base:** `eb343d9` (2.2.05 WDO pool bError auto-restore)

## What was achieved

**Feature: `WDO_MySql` prepared statements (Alt B — server-side PREPARE).**

Hasta 2.2.05 la API sql-facing de `WDO_MySql` era `Query(cSql)` + escape
manual con `Escape()`. Sin protección real contra SQL injection más allá
del escape correcto, y sin forma de re-ejecutar un mismo statement con
distintos valores sin re-parsear el SQL cada vuelta.

2.3.00 añade una capa de prepared statements construida encima del
protocolo texto de MySQL (Alt B en el plan): en vez de wrappear la
familia binaria `mysql_stmt_*` (que requiere construir la struct
`MYSQL_BIND` a mano en byte-buffer, con layout distinto en LLP64 vs
LP64 y sin primitives de Harbour para asignar memoria segura), traducimos
la sintaxis de prepared a los comandos SQL nativos que todas las
versiones de MySQL/MariaDB soportan:

```harbour
oStmt := oConn:Prepare( "SELECT id FROM users WHERE age > ? AND city = :c" )
oStmt:BindParam( 1,   18,      "i" )    // positional
oStmt:BindParam( ":c", "Girona", "s" )  // named
oStmt:Execute()
aRows := oStmt:FetchAll( .T. )
oStmt:Free()
```

Por debajo:

```sql
PREPARE hix_stmt_<tid>_<seq> FROM '<sql-con-?>';
SET @p1 := 18;
SET @p2 := 'Girona';
EXECUTE hix_stmt_<tid>_<seq> USING @p1, @p2;
DEALLOCATE PREPARE hix_stmt_<tid>_<seq>;   -- en Free()
```

Ventajas de esta ruta:
- Cero DynCall nuevo (ningún wrapper de `mysql_stmt_*`).
- Cero código C nuevo (todo se resuelve en `.prg`).
- Layout MYSQL_BIND irrelevante — MySQL parsea y valida los tipos.
- Portable a MariaDB / MySQL 5.7 / 8.0 sin ifdefs.
- Re-Execute reusa la sentencia preparada del servidor: parse una vez,
  ejecuta N veces.

Coste: los valores viajan como texto (no binary), y hay round-trips
extra por los `SET @pN`. Para casos donde el binary protocol sea
crítico (INSERT masivos de decimales, LOBs con `send_long_data`), 2.4
puede añadir Alt A. Para el 95% de tráfico web actual, Alt B basta.

### Parser de SQL

El scanner respeta:
- Literales `'...'` y `"..."` con escape `\` y doblado `''`/`""`.
- Identificadores `` `...` ``.
- Comentarios `-- ...` a fin de línea.
- Comentarios `/* ... */` de bloque.
- `?` → placeholder posicional.
- `:name` → placeholder nombrado (letra o `_` seguido de alfanumérico).

Named + positional se pueden mezclar en la misma sentencia; `BindParam`
acepta índice numérico (1-based) o el nombre (con o sin `:` inicial).

### Tipos soportados en `BindParam`

| cType | Harbour  | SQL literal generado                          |
|-------|----------|-----------------------------------------------|
| `i`   | numeric  | entero (para lógicos, 1/0)                    |
| `n`   | numeric  | decimal con punto (StrTran coma→punto)        |
| `s`   | char     | `'...'` con `wdo_addslashes`                  |
| `d`   | date     | `'YYYY-MM-DD'`                                |
| `t`   | timestamp| `'YYYY-MM-DD HH:MM:SS'`                       |
| `b`   | char     | `x'HEX'` — binary blob                        |
| NIL   | -        | `NULL` literal                                |

Si `cType` se omite en `BindParam`, se infiere del `ValType`.

### Ciclo de vida

- `Free()` extendido: si `lPrepared`, emite `DEALLOCATE PREPARE`
  best-effort (no rompe si la conexión ya está caída).
- Reutilizable: mismo `oStmt` acepta `BindParam` + `Execute` repetidos
  sin re-preparar.
- Compatible con el pool: los statements viven en la conexión del pool
  y se limpian en `Free`. `WDO_Get` → `Prepare` → `Execute` → `Free`
  → `Close` sigue siendo el patrón canónico.

## Bug encontrado durante el desarrollo

`cUsing != ""` en la construcción del `USING @p1, @p2, ...` daba
siempre `.F.` porque con `SET EXACT OFF` (default Harbour) el operador
`!=` sobre strings trata `""` como prefijo de cualquier string —
resultado: el separador `,` nunca se añadía y el server tumbaba
la sentencia con syntax error. Fix: `Len(cUsing) > 0`. La regla ya
está documentada en la HIX bible (§14 "Comparación de strings") pero
cayó de todos modos. Buen recordatorio.
