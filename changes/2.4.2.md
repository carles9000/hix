# HIX v2.4.2

**Date:** 2026-10-15
**Base:** v2.4.1
**Type:** Bug fix + refactor cosmético
**Reportado por:** Charlie (externo) — `z/HIX_parche_ExecuteHrb.md`

## TL;DR

Dos cambios en esta release:

1. **Fix funcional.** Las rutas con acción `.hrb` (`"action": "controllers/login.hrb"`) perdían la petición actual: `UContext()`, `USession()`, `UFlash()`, `UGet()`, `UCookie()`, `URequest()` fallaban con `No exported method HDATA`. El mismo controlador compilado como `.prg` funcionaba sin problemas.

2. **Refactor coherencia.** El subsistema `src/compile/` ahora respeta el prefijo `hix_*` en ficheros y funciones. Sin cambio funcional — solo nombres.

## 1. Bug fix — ExecuteHrb pierde la petición

### Causa raíz

`src/hix_router.prg` (`_HixEvalAction`), la rama `.hrb` llamaba al despachador sin propagar `oReq`:

```harbour
CASE cExt == ".prg"
   xResult := s_oRouteDisp:ExecutePrg( cPhysical, oReq, hClass, nTimeoutMs )

CASE cExt == ".hrb"
   xResult := s_oRouteDisp:ExecuteHrb( cPhysical, nTimeoutMs )      // <- sin oReq
```

`ExecuteHrb` tampoco pasaba `oReq` a `_HixExecWithTimeout`, que arrancaba haciendo `HIX_SetRequest( oReq )` con `oReq = NIL`. El THREAD STATIC `s_oCurrentReq` se borraba y todo lo que leía del request fallaba.

El bug afectaba también al **path con timeout**: el hilo hijo (`_HixThreadExec`) hereda THREAD STATIC vacíos — así que necesita que `oReq` le llegue como parámetro explícito, no por fallback.

### Fix

**`src/hix_dispatcher.prg`:**

```diff
-   METHOD ExecuteHrb(  cPath, nTimeoutMs )
+   METHOD ExecuteHrb(  cPath, nTimeoutMs, oReq )

-METHOD ExecuteHrb( cPath, nTimeoutMs ) CLASS THixDispatcher
+METHOD ExecuteHrb( cPath, nTimeoutMs, oReq ) CLASS THixDispatcher

    LOCAL oHrb
    LOCAL nMs := iif( nTimeoutMs == NIL, ::nExecTimeout, nTimeoutMs )

+   // Fallback: las llamadas internas del dispatcher (ExecutePrg → .hrb,
+   // _HixPreviewExec) corren en el hilo del worker con petición activa.
+   IF oReq == NIL
+      oReq := HIX_GetRequest()
+   ENDIF

    l( "ExecuteHrb: " + cPath )
    oHrb := hb_MemoRead( cPath )

-RETURN _HixExecWithTimeout( oHrb, nMs, cPath )
+RETURN _HixExecWithTimeout( oHrb, nMs, cPath, NIL, oReq )
```

**Guard defensiva** en `_HixExecWithTimeout` — nunca pisar la petición del hilo padre con NIL:

```diff
-   HIX_SetRequest( oReq )
+   IF oReq != NIL
+      HIX_SetRequest( oReq )
+   ENDIF
    HIX_EchoClear()
```

**`src/hix_router.prg`:**

```diff
    CASE cExt == ".hrb"
-      xResult := s_oRouteDisp:ExecuteHrb( cPhysical, nTimeoutMs )
+      xResult := s_oRouteDisp:ExecuteHrb( cPhysical, nTimeoutMs, oReq )
```

### Alcance del bug

Afecta a cualquier `U*` que lea del request desde un controller `.hrb` publicado como ruta:

`UContext`, `USession`, `UFlash`, `UGet`, `UPost`, `UParam`, `UCookie`, `UHeader`, `UBody`, `UJson`, `UFiles`, `UIP`, `UHost`, `UIsAjax`, `UWantsJson`, `URequest`, `URoute`, `UMethod`, `UPath`, …

### Caso de uso que lo destapó

Distribución de un ERP sobre HIX sin fuentes `.prg` en el servidor del cliente (solo `.hrb` compilados). Los loaders `.hrb` y las rutas `.hrb` funcionaban salvo este punto.

## 2. Refactor — prefijo `hix_*` en src/compile/

Para coherencia con el resto de la lib (`hix_dispatcher.prg`, `hix_router.prg`, etc.), el subsistema compile se normaliza.

### Funciones renombradas

| Antes | Después |
|---|---|
| `HIX_Preamble()` | `HIX_CompilePreamble()` |
| `HIX_PreambleLines()` | `HIX_CompilePreambleLines()` |
| `HIX_ErrorFromCompileHash()` | `HIX_CompileErrorFromHash()` |
| `_HixAdjustHashLines()` | `_HixCompileAdjustHashLines()` |
| `_HixReadSourceLine()` | `_HixCompileReadSourceLine()` |

### Ficheros renombrados


Hecho con `git mv` — el historial se preserva.

Callers actualizados en `src/hix_dispatcher.prg`, `src/hix_loader.prg`,
`src/hix_trace.prg` y tests `tests/compile/tests/H08_err_shim.prg`,
`H09_preamble_relocation.prg`.

## Breaking change

Para proyectos externos que usen directamente las APIs de `src/compile/`:

- `HIX_Preamble` → `HIX_CompilePreamble`
- `HIX_PreambleLines` → `HIX_CompilePreambleLines`
- `HIX_ErrorFromCompileHash` → `HIX_CompileErrorFromHash`

Rename duro, sin wrappers de compatibilidad. El motor interno de HIX ya usa los nombres nuevos.
