# HIX v2.5.5

**Date:** 2026-11-22
**Base:** v2.5.4
**Origin:** Bug report del ejemplo `examples/web/crud/` — loop
`/login → POST /auth → redirect /login` con error CSRF, aún con
credenciales correctas.

**Type:** Session + flash lifecycle fix — la ruta GET `/login` no
declara middleware de sesión. `UFlash()` levanta la sesión en lazy
vía `THixSessionProxy:_EnsureLoaded()`, pero sin datos que guardar
`TFlash:Save()` era no-op y el navegador nunca recibía la cookie.
El `@csrf` firmaba un token contra un SID fantasma; el `POST /auth`
abría una sesión nueva con SID distinto, `HIX_MwCsrfCheck` rechazaba
el token (403 → redirect `/login`), y el ciclo se repetía
indefinidamente.

## TL;DR

- `HIX_MwSession()` es ahora **idempotente dentro del request** y
  **emite Set-Cookie al nacer la sesión**, independientemente de si
  algún handler llama a `USession():Save()`. En storage `file` también
  persiste el entry vacío en disco, de modo que el próximo request con
  esa cookie recupera el mismo SID.
- `TFlash:_Sync( lWrite )` mantiene `::hBag` **enlazado por referencia**
  con el bag del `formId` en la sesión. Dos instancias `UFlash()` con
  el mismo `formId` ven los mismos mensajes y no se pisan al guardar.
- `login.prg` del ejemplo crud queda intacto: el programador no tiene
  que añadir `USession():Save()` para obtener un SID estable.

## Cambios

### `src/hix_session.prg`

- `HIX_MwSession( oCtx )` devuelve inmediatamente si
  `oCtx:hData[ "_sid" ]` ya está presente — evita regenerar el SID
  cuando el middleware se ejecuta varias veces dentro del mismo
  request (ruta + lazy-load desde `UFlash`, etc.).
- Nueva bandera `lNew` que marca si el SID se acaba de crear. Cuando
  `lNew=.T.`:
  - Se emite `Set-Cookie` con nombre y TTL de la configuración, para
    que el navegador reciba el SID aunque el handler no haya tocado
    sesión.
  - En modo `storage=file`, se escribe el entry vacío al disco. El
    próximo request con esa cookie carga el SID existente en vez de
    generar otro.
- Sesiones existentes (`hData[ "_sid" ]` llega vía cookie) siguen
  sin renovar cookie — la actualización de TTL queda reservada al
  `Save()` explícito, como antes.

### `src/hix_flash.prg`

- Nuevo `METHOD _Sync( lWrite )` privado:
  - Si el bag del `formId` ya existe en la sesión pero apunta a otro
    objeto (p. ej. un `Save()` anterior lo borró y otra instancia lo
    recreó), fusiona las escrituras locales (`hb_HMerge`) y reconecta
    `::hBag` a la referencia compartida. Un bag desconectado sólo
    contiene claves escritas por esta instancia, así que la fusión
    nunca resucita mensajes consumidos.
  - Si el bag no existe aún y hay contenido propio o es una escritura
    (`lWrite=.T.`), (re)enlaza `::hBag` al bag del `formId` en la
    sesión. En lecturas sin contenido no crea nada, para no dejar
    grupos vacíos.
- Todos los métodos públicos (`Set`, `Get`, `Has`, `Delete`, `Clear`,
  `Save`) llaman a `_Sync()` antes de tocar `::hBag`, garantizando
  consistencia entre instancias.
- `Save()` mantiene el no-op cuando `lDirty=.F.`; ya no necesita
  forzar `oSess:Save()` porque el middleware emite la cookie cuando
  la sesión nace.

## Patrón resuelto

Antes:

```harbour
// GET /login (sin middleware de sesión)
oFlash := UFlash( "login" )          // lazy → crea SID
cError := oFlash:Get( "error" )      // vacío
USendView( "sys/login.html", "", "" ) // @csrf firma con SID nuevo
// -> Set-Cookie NO se envía (TFlash:Save era no-op)
```

Ahora:

```harbour
// GET /login
oFlash := UFlash( "login" )          // lazy → crea SID + Set-Cookie
cError := oFlash:Get( "error" )      // vacío
USendView( "sys/login.html", "", "" ) // @csrf firma con SID estable
// -> El navegador recibe la cookie; POST /auth valida el token OK
```

## Impacto

- **Programador:** ninguno. El ejemplo crud no cambia, el patrón
  `UFlash()` + `@csrf` sigue funcionando sin pedir sesión explícita.
- **Compatibilidad:** cero cambios de API. Los Set-Cookie extra
  afectan solo a rutas que antes **no** emitían cookie por omisión
  de `Save()`; ninguna ruta pierde comportamiento previo.
- **Storage=file:** un entry vacío extra en disco por SID nuevo.
  La huella es la misma que si el handler llamase `Save()` sin
  datos — el próximo GC lo recoge si no se renueva.
