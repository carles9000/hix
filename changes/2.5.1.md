# HIX v2.5.1

**Date:** 2026-11-21
**Base:** v2.5.0
**Plan:** `.claude/plans/2026-11-21_2038 admin_migrar_a_pbkdf2.md`
**Origin:** Claim 5 del informe de revisión externa v2.5.

**Type:** Security — Migrar el almacenamiento de la contraseña del
panel admin de HMAC-SHA256 (una pasada) a PBKDF2-HMAC-SHA256
(600 000 iteraciones) + comparación constant-time sobre la firma
de la cookie de sesión.

## TL;DR

`hix_admin.prg` ya no guarda `admin.password` como
`HMAC_SHA256(pass, secret)` — un hash sin stretching que un
atacante con el `hix.json` filtrado podría romper offline a
billones de intentos/segundo.

A partir de 2.5.1, el setup guarda un record **PBKDF2-SHA256** con
el formato portable de `HIX_PasswordHash`: `passalg / passiter /
salt / passhash`. La verificación usa `HIX_PasswordVerify`
(constant-time, 600k iteraciones por defecto — OWASP 2026).

La firma de la cookie `hix_admin` se verifica ahora con
`HIX_ConstantEq` en lugar de `!=`, cerrando un timing side-channel
que permitía refinar la firma iterativamente.

## Migración automática desde v2.5.0

**Transparente**. Un admin existente con `admin.password` legacy
sigue iniciando sesión con su contraseña. Al primer login OK:

1. Se re-hashea la contraseña con PBKDF2 (`passalg`, `passiter`,
   `salt`, `passhash` nuevos).
2. Se rota `admin.secret` — invalida cookies emitidas con el
   secret viejo. Los otros clientes autenticados vuelven a entrar.
3. Se elimina `admin.password` (legacy) del `hix.json`.
4. Se guarda el hix.json.

Se emite un `lw()` en el log: `Admin password upgraded from
legacy HMAC to PBKDF2`.

Si no hay admin configurado todavía, `/hix-setup` crea el usuario
directamente en el formato nuevo.

## Cambios

### `src/hix_admin.prg`

- `_HixAdminSetupApply` → usa `HIX_PasswordHash`; genera un
  `secret` fresco con `_HIX_PASSWORDSALT` (16 bytes OS-seeded,
  hex lower).
- `_HixAdminHasCredentials` → acepta formato nuevo
  (`passhash`) **o** legacy (`password`) durante la ventana de
  migración.
- `_HixAdminVerifyPassword` nuevo — PBKDF2 por defecto, fallback a
  HMAC-SHA256 solo si no hay `passhash`. La comparación legacy usa
  `HIX_ConstantEq`.
- `_HixAdminMaybeRehash` nuevo — rehash transparente post-login:
  legacy → PBKDF2 + rotación de secret; PBKDF2 obsoleto →
  rederivar con `nRounds` vigente.
- `_HixAdminNewSecret` nuevo — helper para rotar secret.
- `_HixAdminVerify` (firma cookie) → `HIX_ConstantEq` en vez de
  `!=`.

### `hix.json` — layout `admin`

**Formato anterior (v2.5.0)**:
```json
"admin": {
   "user":     "charly",
   "secret":   "a1b2…",
   "password": "deadbeef…"    // HMAC_SHA256(pass, secret)
}
```

**Formato nuevo (v2.5.1+)**:
```json
"admin": {
   "user":     "charly",
   "secret":   "a1b2…",       // sigue firmando la cookie
   "passalg":  "PBKDF2-SHA256",
   "passiter": 600000,
   "salt":     "…32 hex chars…",
   "passhash": "…64 hex chars…"
}
```

### Tests

- `tests/unit/src/hix_test_admin.prg` — nuevo grupo `Admin`:
  login OK, password/user incorrectos, legacy upgrade con
  verificación de rotación de secret y borrado de
  `admin.password`, cookie válida + firma manipulada (contra
  `HIX_AdminCheck`).
- `tests/unit/src/hix_test_admin_setup_api.prg` — actualizado
  para el nuevo record (comprueba `passalg`, `passiter`, salt/hash
  length, `HIX_PasswordVerify` end-to-end, y que el campo legacy
  `password` queda limpio tras el setup).

## Riesgo operativo

- **Coste de login**: 600k iteraciones PBKDF2 añaden ~200-400 ms
  al POST `/hix-login`. Admin no es un endpoint de alto QPS;
  aceptable.
- **Rotación de secret en upgrade legacy**: las sesiones admin
  activas se invalidan — los usuarios deben re-loguear una vez.
  Es el trade-off para evitar que un secret débil siga en
  circulación.
- **Fail-closed**: si `libcrypto` no está disponible, el setup
  retorna `cErr="hash_failure"` y no se configura admin (en
  lugar de caer silenciosamente a un hash más débil).

## Fuera de scope

- `HixMwJwt` — ya usa HMAC-SHA256 correctamente (JWT estándar no
  contempla stretching sobre la firma).
- `HixMwCsrf` — ya usa `HIX_ConstantEq`.
- Rotación automática periódica de `admin.secret` fuera del
  upgrade legacy — queda para otra iteración.
