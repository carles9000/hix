# HIX v2.3.03

**Date:** 2026-10-01
**Base:** `2240d63` (2.3.02 opt-in WDO metrics + default error handler)

## What was achieved

Alt A — **prepared statements sobre protocolo binario nativo MySQL**.
Nueva clase `WDO_MySqlStmtBin` que se integra con el pool WDO existente
y comparte la misma superficie de binding que Alt B (texto). Cubre los
casos donde Alt B tenía overhead o perdía fidelidad: **BLOBs grandes**,
**binarios con NUL bytes embebidos**, **INSERT masivo**.

Cero cambios en Harbour core — todo vive en wrappers HIX (`src/wdo/`)
sobre `hb_DynCall` + un `#pragma BEGINDUMP` con 7 helpers C de
poke/peek sobre `MYSQL_BIND`.

---

## API pública nueva

```harbour
oStmt := oConn:PrepareBin( cSql )              //  default .T. → Alt A binario
oStmt := oConn:PrepareBin( cSql, .T. )         //  explícito → Alt A
oStmt := oConn:PrepareBin( cSql, .F. )         //  delega → Alt B texto

oStmt:BindParam( nIdx, xValue [, nType ] )     //  1-based; inferencia por ValType
oStmt:BindLong(  nIdx, cData )                 //  chunk para send_long_data
oStmt:Execute()
oStmt:AffectedRows()                           //  mysql_stmt_affected_rows
oStmt:LastInsertId()                           //  mysql_stmt_insert_id
oStmt:Close()                                  //  idempotente; libera pStmt + buffers
```

Mismos nombres de método que Alt B — el handler puede intercambiar
`Prepare`/`PrepareBin` sin tocar el resto del código. Guía completa:
[`docs/mysql/prepared_statements_bin.md`](../docs/mysql/prepared_statements_bin.md).

## Diseño

### Layout `MYSQL_BIND` dual

Windows LLP64 (`long`=4) y Linux LP64 (`long`=8) producen offsets
distintos a partir de `buffer_length`:

| Campo | Windows | Linux |
|---|---:|---:|
| `sizeof(MYSQL_BIND)` | **104** | **112** |
| `buffer_type`        | 84  | 96  |
| `is_unsigned`        | 89  | 101 |
| `is_null_value`      | 91  | 103 |

Offsets anteriores (`length / is_null / buffer / buffer_length`)
coinciden en los dos ABI (todo pointer de 8 bytes o `ulong` alineado).
Resolución runtime en `_WdoBindLayoutInit` según `"Windows" $ OS()`.

Smoke test en el primer `PrepareBin` del proceso: `SELECT ?` bindeando
`LONG=42`, bind_param + execute. Si falla, log loud con `mysql_get_client_info`
+ `hb_Version` — blindaje contra MySQL 9.x cambiando ABI en el futuro.

### Fix crítico — `my_bool` sobre Win64 x64 ABI

`mysql_stmt_bind_param` y `mysql_stmt_send_long_data` retornan
`my_bool` (1 byte). Leerlos con `HB_DYN_CTYPE_BOOL` sobre Win64 lee
basura de los bytes altos de RAX → falsos positivos intermitentes
(bind OK con `rc=0x3F01`, interpretado como `true`).

Fix: wrappers cambiados a `HB_DYN_CTYPE_INT` + `hb_bitAnd(rc, 0xFF)
!= 0`. Documentado en memoria `project_dyncall_my_bool_win64.md`.

### Streaming BLOB con `send_long_data`

`BindLong( nIdx, cData )` acumula chunks sobre el mismo índice.
`Execute()` trocea en slices de 64 KB antes de emitir
`mysql_stmt_send_long_data` — seguro contra `max_allowed_packet`
agresivos del servidor sin desperdiciar paquetes para payloads
pequeños.

### `BindLong` en Alt B — paridad de API

Alt B no tiene send_long_data (es protocolo texto), pero expone
`BindLong( nIdx, cData )` que concatena contra `BindParam` del mismo
slot. Así una app puede usar Alt A o Alt B con el mismo código fuente.

### Entry point unificado

`PrepareBin` es un solo método con flag `lBinary`. Permite:

- Default Alt A sin preocuparse por el flag.
- A/B testing cambiando una variable local.
- Rutas donde Alt A todavía no cubre (SELECT con FetchAll — ver §9 de
  la guía Alt A) delegan explícitamente con `.F.`.

## Notas de diseño

- **Cero cambios en Harbour core.** Condición innegociable del
  proyecto. Los 7 helpers C viven en `#pragma BEGINDUMP` al final de
  `wdo_mysql_stmt_bin.prg`.
- **Compatibilidad total con Alt B.** `oConn:Prepare(cSql)` sigue
  devolviendo `WDO_MySqlStmt` como siempre. `PrepareBin` es un entry
  point nuevo, opt-in.
- **Buffers Harbour vs C.** `MYSQL_BIND.buffer` debe apuntar a memoria
  estable durante `Execute`. Harbour strings satisfacen esto si no se
  reasignan — se conservan vivos en `::aBuffers[ nIdx ]` hasta
  `Close()`.
- **SELECT no soportado hoy.** Ejecutar `SELECT` con `PrepareBin` no
  falla pero no expone fetch binario (`mysql_stmt_result_metadata` +
  `mysql_stmt_bind_result` + `mysql_stmt_fetch`). Para lecturas usar
  Alt B (`Prepare` + `FetchAll`) o `oConn:Query` directo. Pendiente
  en `pendientes.md §1` para v2.3.04.
- **Métricas.** Alt A instrumenta `WDO_MetricQuery` con bucket
  `"PREPAREBIN "`/`"EXECBIN "` para separarlo de Alt B en el
  dashboard — facilita A/B testing con `HIX_MetricsJson`.
