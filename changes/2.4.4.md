# HIX v2.4.4

**Date:** 2026-10-19
**Base:** v2.4.3
**Type:** Feature — WDO PostgreSQL driver

## TL;DR

Driver PostgreSQL para WDO completo, con la misma API y pool que el driver
MySQL. Monta `libpq` vía `hb_LibLoad` / `hb_DynCall` (sin `hbpgsql`), expone
la clase `WDO_PG` + `WDO_PgStmt` sobre la base `WDO`, y añade un pool
compartido registrable bajo la clave `"PG"` (o cualquier otra) para que
`WDO_Get("PG")` funcione thread-safe desde los workers.

Suite nueva `tests/wdo/test_wdo_pg.exe` — **69/69 passed** contra
PostgreSQL 18 local. Suite global del server **inalterada** (sin regresión
sobre el driver MySQL).

---

## Qué añade

### 1. `src/wdo/pg/wdo_pg.prg` — clase `WDO_PG FROM WDO`

Mismo contrato que `WDO_MySql`. Métodos públicos relevantes:

- `New( cServer, cUser, cPwd, cDb, nPort, lOpen, cDllPath )`
- `Open()` / `Close()` / `Ping()` / `IsAlive()` / `Reconnect()`
- `Query( cSql )` → `WDO_PgStmt`
- `Exec( cSql )` → nº filas afectadas (`PQcmdTuples`)
- `BeginTrans()` / `Commit()` / `Rollback()` / `Transaction( bCode )`
- `Last_Insert_Id()` — vía `lastval()` sobre la secuencia activa
- `Escape( hRow )` — basado en `wdo_pg_addslashes` (doblado de `'`)
- `ServerInfo()` / `GetDllVersion()` / `GetClientInfo()` / `GetEncoding()`
- `SetClientEncoding( cEnc )`

Internamente envuelve `PQconnectdb, PQstatus, PQexec, PQresultStatus,
PQresultErrorMessage, PQntuples, PQnfields, PQfname, PQftype, PQfsize,
PQfmod, PQgetvalue, PQgetisnull, PQgetlength, PQcmdTuples, PQclear,
PQfinish, PQlibVersion, PQserverVersion, PQdb, PQhost, PQuser, PQport,
PQsetClientEncoding, PQclientEncoding, PQfreemem` como métodos
`PQ*()` thin wrappers vía `hb_DynCall`.

**Preflight TCP** (`_WdoPgTcpProbe`) antes de `PQconnectdb` evita el hang
de ~2 min cuando el servidor no escucha.

**Resolución de DLL** (`_WdoPgResolveDll`) prueba override → env
(`HIX_PG_DLL`, `WDO_PG_DLL`) → `exedir\dll` → default `libpq.dll`.
Expone `cDllSource` para diagnóstico ("override", "env", "exedir",
"default"). Las 4 DLLs runtime (`libpq, libiconv-2, libintl-9,
libwinpthread-1`) viven en `resources/wdo/pg/dll/`.

**Pool guard** (`WDO_PgNewGuard( .T./.F. )`): emite `WARN` si se crea
`WDO_PG():New()` dentro de un request HTTP (indica que el handler no
está usando el pool). Default `.T.`.

### 2. `src/wdo/pg/wdo_pg_stmt.prg` — clase `WDO_PgStmt FROM WDO`

- `Fetch( aNoEscape )` → array de columnas (string). Si la conexión tiene
  `lWeb=.T.` (default), aplica HTML-escape salvo que la columna esté en
  `aNoEscape`.
- `Fetch_Assoc( aNoEscape )` → hash `{ cColName => cValue }`
- `FetchAll( lAssoc, aNoEscape )` → array de arrays/hashes
- `Count()` / `FCount()` → filas / columnas
- `LoadStruct()` → `aStruct[ i ] = { cName, cType, nSize, nDec }` con
  mapping `oid` → tipo WDO (`int4/int8/numeric/float → "N"`,
  `varchar/text → "C"`, `date/timestamp → "D"`, `bool → "L"`, resto `"C"`).
- `Free()` — libera el `PGresult` (idempotente vía `::lFreed`).

### 3. `src/wdo/pg/wdo_pg_pool.prg` — helpers del pool

- `WDO_InitPoolPg( cHost, cUser, cPwd, cDb, nPort, nSize, nTimeoutMs,
  lPing, bError, cDllPath )` — API posicional, misma forma que
  `WDO_InitPoolMySql`.
- `WDO_InitPoolPgEx( cKey, hParams )` — API hash. Es la que consume
  `HIX_InitPoolsFromConfig()` cuando `hix.json > databases.<pool>:
  { driver: "pg", ... }`. Claves adicionales no cubiertas por el
  posicional: `sslmode`, `application_name` (default `"hix-worker"` →
  visible en `pg_stat_activity`), `client_encoding`, `read_timeout_s`
  (→ `statement_timeout` server-side), `connect_timeout_s`.
- `WDO_EndPoolPg()` — desregistra y cierra el pool `"PG"`.
- `WDO_GetPg()` — azúcar sobre `WDO_Get("PG")`.

Registra el pool con `WDO_RegisterPool( cKey, oPool )`, por lo que
`WDO_Get(cKey)` y `WDO_ReleaseAllThread()` funcionan igual que para MySQL
sin cambios en el dispatcher.

### 4. `src/wdo/wdo_config.prg` — reconocimiento de `driver: "pg"`

Añadido `CASE "pg"` / `CASE "postgres"` / `CASE "postgresql"` que delega
en `WDO_InitPoolPgEx`. Permite declarar un pool PostgreSQL íntegramente
desde `hix.json`:

```json
"databases": {
   "PG": {
      "driver":           "pg",
      "host":             "127.0.0.1",
      "port":             5432,
      "user":             "postgres",
      "pwd":              "secret",
      "db":               "myapp",
      "pool_size":        5,
      "timeout_ms":       5000,
      "sslmode":          "disable",
      "application_name": "hix-worker",
      "client_encoding":  "UTF8"
   }
}
```

### 5. `src/wdo/include/wdo_pg.ch`

- `WDO_PG_DEFAULT_PORT` = 5432
- `WDO_PG_POOL_KEY` = "PG"
- `WDO_PG_DEFAULT_APPNAME` = "hix-worker"
- Constantes `CONNECTION_OK`, `PGRES_COMMAND_OK`, `PGRES_TUPLES_OK`,
  `PGRES_EMPTY_QUERY`, `PGRES_FATAL_ERROR`.
- OIDs comunes (`PG_OID_BOOL=16, INT4=23, TEXT=25, FLOAT8=701, DATE=1082,
  TIMESTAMP=1114, NUMERIC=1700, VARCHAR=1043`, etc.).

### 6. `tests/wdo/test_wdo_pg.*`

- `test_wdo_pg.prg` — 69 asserts estructurados en 4 fases:
  - **Phase 1 Offline API**: ctor, type (`PG`), `nPort`,
    `application_name` default, `wdo_pg_addslashes`, `Escape(hRow)`.
  - **Preflight**: probe TCP → aborta la fase online si el servidor
    no está arriba.
  - **Phase 1 Online API**: Open, IsAlive, ServerInfo, Query/Fetch,
    Fetch_Assoc, DDL/DML, single-quote escape, `Last_Insert_Id`,
    `BeginTrans/Commit/Rollback`, `Transaction( {|o| ... } )`, mapping
    OID → tipo WDO, `WDO_PgCountOpen`, `WDO_PgNewGuard` default,
    `oStmt:lError` y `oConn:cError` tras SQL inválido, `Close()`.
  - **Phase 2 Pool**: `WDO_InitPoolPg`, `WDO_PoolStats("PG")`,
    `WDO_Get` × 2, timeout de 3ª adquisición, `WDO_ReleaseAllThread`,
    `WDO_EndPoolPg`.
  - **Phase 2b Pool Ex**: `WDO_InitPoolPgEx("PG_EX", hParams)` con
    `application_name="hix-test-pg"` → verifica contra
    `pg_stat_activity` que el nombre llega al servidor.
- `test_wdo_pg.hbp` — compila el ejecutable standalone.
- Script `go_pg_msvc64.bat test_wdo_pg` (reutiliza el batch genérico).

Flags útiles del test: `--cli` para salida sin pausa final;
sin flags espera `inkey(0)`.

## Breaking changes

Ninguno. Driver aditivo bajo `src/wdo/pg/` + 3 líneas en
`hix_server.hbp` + 1 `CASE` en `wdo_config.prg`. Las apps existentes que
usen MySQL siguen compilando y pasando tests sin tocar nada.
