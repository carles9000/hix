# HIX v2.3.07

**Date:** 2026-10-03
**Base:** v2.3.06 (WDO MySql docs+examples)

## What was achieved

Fix crítico de saturación del pool MySQL + mejoras de observabilidad en el
ejemplo Hi.

- **`WDO_ReleaseAllThread()` conectada al dispatcher** — el hook existía
  implementado en `wdo_pool.prg` desde el diseño original pero nunca se
  llamaba. Con el fix, los 4 bloques FINALLY de `hix_dispatcher.prg`
  invocan `WDO_ReleaseAllThread()` tras `HIX_CloseDbfAreas()`. Cualquier
  controller que no llegue a `oConn:Close()` (excepción, RETURN temprano,
  cualquier motivo) devuelve las conexiones al pool automáticamente al
  terminar el request. El pool ya no se puede saturar por leaks de
  controllers individuales. Fast-path `sl_HasPools == .F.` garantiza
  coste ~0 en apps sin WDO.

- **Controllers MySQL de Hi con TRY/CATCH/FINALLY** — `api_mysql_demo.prg`,
  `api_mysql_test.prg`, `api_mysql_bench.prg` envuelven el bloque de trabajo
  en TRY/CATCH/FINALLY con `oConn:Close()` en FINALLY. Buena práctica de
  logging explícito; ya no crítico para la salud del pool.

- **Pool stats widget en bench** — nueva ruta `GET /api/mysql-pool-stats`,
  widget "MySQL Pool" en `bench-test.html` con busy/size, barra de progreso,
  indicador "Max busy / this run" y refresco a 300 ms durante el bench
  (3 s en reposo).

- **Logging MySQL via `_l()`** — los errores de los controllers se emiten
  con prefijo `[mysql:demo/test/bench]` al log estándar HIX. Eliminado el
  loader `mysql_log.prg` (función no resolvible desde .hrb dinámicos).
