# HIX v2.3.05

**Date:** 2026-10-01
**Base:** v2.3.04 (Alt A SELECT fetch binario)

## What was achieved

Fix defensivo en el driver MySQL: `mysql_thread_init()` por cada OS
thread que ejecuta un comando libmysql. Las conexiones del pool se
crean en el thread main (que implícitamente inicializa libmysql) pero
se consumen desde los workers HIX en OS threads distintos; sin
`mysql_thread_init` explícito, libmysql queda sin TLS en ese thread →
comportamiento indefinido bajo concurrencia (cuelgues intermitentes,
corrupción silenciosa).

El guard es idempotente y vive detrás de un `THREAD STATIC` boolean —
coste tras la primera llamada por worker: una comparación local.

## API

Métodos nuevos en `WDO_MySql`:

```harbour
oConn:mysql_thread_init()   // 0 = OK; idempotente a nivel libmysql
oConn:mysql_thread_end()    // libera TLS (no se llama automáticamente)
oConn:ThreadInitOnce()      // guard idempotente via THREAD STATIC
```

`ThreadInitOnce()` se invoca automáticamente al top de:

- `mysql_query()`
- `mysql_stmt_execute()`

El resto de métodos (connect, close, prepare, bind, store_result, …)
heredan el init vía la primera llamada a query/execute del thread.

## Diseño

### `THREAD STATIC sl_ThreadInited`

Cada OS thread (worker HIX) tiene su propia copia inicializada a `.F.`.
La primera llamada que pasa por `ThreadInitOnce` dispara
`mysql_thread_init` + flip del flag; las subsiguientes son no-op.

### `my_bool` INT+mask — consistente con v2.3.03

`mysql_thread_init` retorna `my_bool` (1 byte). Mismo bug Win64 descrito
en `project_dyncall_my_bool_win64.md`: leer como `HB_DYN_CTYPE_BOOL`
coge basura de RAX alto. Fix: `HB_DYN_CTYPE_INT` + `hb_bitAnd(rc, 0xFF)`.

### Por qué no llamar `mysql_thread_end`

HIX no expone hook de salida de worker. El cost de dejar TLS colgando
hasta el shutdown del proceso es despreciable (unos cientos de bytes
por thread) y el riesgo de llamar `thread_end` prematuramente — por
ejemplo si un worker lo invoca y luego hace otra query — es mayor. Se
expone el método para scripts que gestionen su propio ciclo de vida.

## Notas de diseño

- **Cero cambios en Harbour core.** Los 3 métodos nuevos son wrappers
  `hb_DynCall` sobre funciones ya exportadas por `libmysql`.
- **Overhead cero tras el primer hit.** `THREAD STATIC` compare + jump
  — menos coste que un `IF Empty()`.
- **Why only `query` + `stmt_execute`.** Son los únicos entry points
  que un worker alcanza sin pasar por `New()`/`Connect()` (que ya
  corren en main). Añadir el guard también en `connect/close/prepare`
  no aporta — o estás en main (init implícito) o ya pasaste por un
  execute previo.
- **MySQL Showcase (example app).** Cambios no afectan la lib pero
  demuestran el stack bajo carga real: 6 queries aleatorias sobre
  dataset de 300k empleados / 2.8M salarios, cada card re-ejecutable
  independientemente, UI reactiva con tabs y modales Bootstrap 5.3.
