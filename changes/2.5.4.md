# HIX v2.5.4

**Date:** 2026-11-22
**Base:** v2.5.3
**Plan:** `.claude/plans/2026-11-22_0722 claim3_http_framing_strict.md`
**Origin:** Claim 3 del informe de revisión externa v2.5.

**Type:** HTTP framing strict — RFC 9112 §6.1 hardening. El parser de
requests aceptaba combinaciones ambiguas que habilitan request
smuggling (dos `Content-Length`, `Transfer-Encoding` sin implementar,
`Content-Length` con valores no estrictos) y no marcaba como
corrupto el keep-alive tras un body truncado. Cuatro fixes
independientes (F1-F4).

## TL;DR

Cualquier request con framing ambiguo ahora se rechaza con un status
determinista antes de llegar al handler:

| Vector | Status | Error interno |
|---|---|---|
| Dos `Content-Length` (aunque los valores coincidan) | 400 | `HIX_REQ_ERR_BADREQ` |
| `Content-Length: 10, 10` (coma) | 400 | `HIX_REQ_ERR_BADREQ` |
| `Content-Length: abc` / `-5` / `0x10` / `` (vacío) | 400 | `HIX_REQ_ERR_BADREQ` |
| `Content-Length: 1000000000` (> `HIX_MAX_BODY_SIZE`) | 413 | `HIX_REQ_ERR_TOOLARGE` |
| Cualquier `Transfer-Encoding` de entrada | 501 | `HIX_REQ_ERR_TE_UNSUPPORTED` |
| `Transfer-Encoding` + `Content-Length` | 400 | `HIX_REQ_ERR_BADREQ` |
| Body truncado (peer cierra antes de `Content-Length`) | — | `HIX_REQ_ERR_TRUNCATED`, `keep-alive=OFF` |

El worker HTTP cierra keep-alive en todos los casos — una conexión con
framing ambiguo no se recicla.

## Cambios

### F1 — `src/hix_request.prg` · duplicate headers rejection

- Tracking `hSeenSingle` dentro del loop de parsing de headers.
- Cualquier segunda aparición de `content-length`, `transfer-encoding`
  o `host` → `nReadError = BADREQ`, `lKeepAlive = .F.`, `RETURN .F.`.
- `Content-Length` con `,` → también `BADREQ` (vector "10, 10" que
  algunos parsers aceptan como el mismo valor).

### F2 — `src/hix_request.prg` · Content-Length strict parser

- Nuevo helper `STATIC FUNCTION _HixParseContentLength( cRaw )`:
  - `-1` si no numérico, signo, hex, espacios internos o vacío.
  - `-2` si `> HIX_MAX_BODY_SIZE` (reutiliza rama 413 del worker).
  - `>= 0` numérico válido.
- `Read()` invoca el helper después del parsing de headers — rechaza
  con el código apropiado antes de llamar al handler.
- `ContentLength()` también usa el helper para no divergir del parser
  (evita el caso "parser dice BADREQ, `ContentLength()` devuelve basura").

### F3 — `src/hix_request.prg` + `src/hix_worker_http.prg` · Transfer-Encoding rejection

- `Read()` detecta `Transfer-Encoding` tras parsing de headers:
  - Si coexiste con `Content-Length` → `BADREQ` (defensa smuggling).
  - Sin `CL` → `HIX_REQ_ERR_TE_UNSUPPORTED`, keep-alive off.
- Política v1: **todo** `TE` rechazado, incluido `identity`. HIX no
  implementa chunked decoder y RFC 9112 depreca `identity` como token
  de entrada. Cuando haya chunked support real se reevalúa.
- `_HixHTTPProcessOne` añade rama `HIX_REQ_ERR_TE_UNSUPPORTED` → 501
  con payload JSON `{"error":"REQ_TE_UNSUPPORTED"}`.

### F4 — `src/hix_request.prg` · ReadBody truncation detection

- `ReadBody()` reemplaza el `Read()` único por bucle hasta completar
  `Content-Length`. Salida en `NIL` o retorno de longitud `0` — nunca
  por `Empty()` (un `Space(N)` del peer hubiera salido prematuramente).
- Si `Len(cData) < nLen` al salir del loop → `HIX_REQ_ERR_TRUNCATED`,
  `lKeepAlive = .F.`. El handler recibe el body parcial pero la
  conexión no se recicla, evitando que el fragmento sobrante contamine
  el siguiente request.

### Constantes nuevas — `src/include/hix_const.ch`

```c
#define HIX_REQ_ERR_TE_UNSUPPORTED 4
#define HIX_REQ_ERR_TRUNCATED      5
```

### i18n — `src/lang/hix_lang.prg`

6 claves nuevas en la sección "Request errors":
`REQ_BODY_TRUNCATED`, `REQ_TE_UNSUPPORTED`, `REQ_DUP_CONTENT_LENGTH`,
`REQ_INVALID_CONTENT_LENGTH`, `REQ_TE_AND_CL_CONFLICT`, `REQ_DUP_HEADER`.

### Worker — `src/hix_worker_http.prg`

Branches explícitas tras `oReq:Read() == .F.`:
- `HIX_REQ_ERR_BADREQ` → 400 (preexistente).
- `HIX_REQ_ERR_TE_UNSUPPORTED` → 501 (nuevo).
- `HIX_REQ_ERR_TOOLARGE` → 413 (nuevo; antes solo se chequeaba después
  del `Read()` vía `ContentLength() + prebuf`).
- Todas fijan `lKeepAlive := .F.` antes de `RETURN .F.`.

## Migración desde v2.5.3

**Ninguna acción requerida** para apps que ya respetaban RFC 9112. Si
una integración (proxy, SDK, test harness) enviaba `Transfer-Encoding`
hacia HIX, ahora recibe `501` en lugar de ser procesada como si el
header no existiera. Mismo caso para `Content-Length` con formato no
estricto.

Clientes que enviaban body con `Content-Length` correcto pero cerraban
antes de completar lo anunciado (bug cliente) ahora verán un keep-alive
cortado — comportamiento correcto; antes HIX reciclaba la conexión con
bytes de body sobrantes que corrompían el siguiente request.

## Fuera de scope

- No implementamos chunked transfer-encoding de entrada. Queda para una
  release futura cuando el parser pueda decodificar frames chunked de
  forma segura.
- No tocamos el emisor HIX de `Transfer-Encoding: chunked` (salida) —
  sigue intacto, el fix sólo cubre entrada.
- No cambiamos el límite `HIX_MAX_BODY_SIZE` (10 MiB) ni añadimos un
  knob de configuración para relajar la política de TE.
