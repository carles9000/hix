# HIX v2.1.04

**Fecha:** 2026-09-11
**Base:** `c4982d3` (2.1.03)

## Qué se ha conseguido

Aislamiento de métricas por protocolo y rediseño completo del panel
`/server-info`. La motivación fue detectar que los streams SSE largos
inyectaban su duración (segundos, incluso minutos) en `req_ms_avg`,
desplazando el promedio de HTTP síncrono y haciendo que un pico
transitorio quedase colgado del panel durante todo el uptime. Se
crean buckets separados para stream y WebSocket, y de paso se
resuelve el miscount de `active_http` cuando un request cambia a
modo streaming.

## Cambios en la librería

### 1. Buckets de métrica separados

`src/include/hix_const.ch` añade:

```harbour
#define HIXM_STREAM_MS_MAX      "stream_ms_max"
#define HIXM_STREAM_MS_AVG      "stream_ms_avg"
#define HIXM_STREAM_MS_COUNT    "stream_ms_count"
#define HIXM_STREAM_MS_MAX_AT   "stream_ms_max_at"
#define HIXM_STREAM_MS_MAX_PATH "stream_ms_max_path"
#define HIXM_WS_MS_MAX          "ws_ms_max"
#define HIXM_WS_MS_AVG          "ws_ms_avg"
#define HIXM_WS_MS_COUNT        "ws_ms_count"
```

`THixMetrics:Init/Reset` inicializan los nuevos contadores. `ToJson()`
los emite automáticamente al recorrer `hCounters`.

### 2. `HIX_MetricTiming( nMs, cPath, lStream )`

Firma extendida — el 3er argumento por defecto es `.F.` (backward
compatible). Cuando `lStream = .T.`, el update va al bucket
`STREAM_MS_*` con su propio slowest-path tracker. El resto de callers
existentes no requieren cambio.

### 3. `HIX_MetricWsTiming( nMs )` per-frame

Nuevo wrapper + `METHOD UpdateWsTiming( nMs )`. Se llama dentro de
`_HixWSFrameLoop` **justo después** del callback `bOnMessage` para
frames TEXT/BINARY:

```harbour
CASE nOpcode == WS_OP_TEXT .OR. nOpcode == WS_OP_BINARY
   HIX_Metric( HIXM_BYTES_IN, Len( cPayload ) )
   tFrame := hb_DateTime()
   IF bOnMessage != NIL
      Eval( bOnMessage, oConn, cPayload, nOpcode )
   ENDIF
   HIX_MetricWsTiming( Int( ( hb_DateTime() - tFrame ) * 86400000 ) )
```

**Semántica**: mide el coste de procesar cada mensaje entrante, no la
duración de la sesión completa (que antes ensuciaba `avg` con
minutos). El coste real de un callback trivial (echo) queda por
debajo de la resolución del reloj Windows (`hb_DateTime()` ~1-15 ms),
así que Avg/Max mostrarán 0 hasta que el handler haga trabajo real
(DB query, JSON encode, cálculo). Es la métrica correcta — solo que
sub-ms es indistinguible en Windows sin QueryPerformanceCounter.

### 4. Counter swap HTTP↔OTROS al entrar en stream

`THixRequest` gana `DATA lWasStream INIT .F.` (persistente entre
requests keep-alive del mismo worker). `RespondStart` intercambia
contadores atómicamente:

```harbour
IF ! ::lWasStream
   HIX_MetricDec( HIXM_ACTIVE_HTTP  )
   HIX_Metric(    HIXM_ACTIVE_OTROS )
ENDIF
::lStreaming := .T.
::lWasStream := .T.
```

`HIX_WorkerHTTP` recibe `lStreamMode` por referencia, lo activa si
`oReq:lWasStream` tras el dispatch, y decrementa el contador correcto
al salir del worker. Antes: una SSE contaba como `active_http` porque
el request empezó como HTTP normal — el panel mostraba HTTP=1/WS=0/SSE=0
mientras había un stream vivo. Ahora: HTTP=0/WS=0/SSE=1.

`HIX_MetricTiming` recibe `oReq:lWasStream` como 3er arg, así el
tiempo del stream se registra en `STREAM_MS_*` y no en `REQ_MS_*`.

## Rediseño de `/server-info`

Panel completamente reorganizado en `views/serverinfo.html` +
`controllers/api_serverinfo.prg`.

### JSON expuesto por el controller

Nuevas claves en la respuesta:

```json
{
  "timing":        { "ms_max", "ms_avg", "count", "max_at", "max_path" },
  "timing_stream": { "ms_max", "ms_avg", "count", "max_at", "max_path" },
  "timing_ws":     { "ms_max", "ms_avg", "count" },
  "limits":        { "http", "ws", "sse", "maxconn" }
}
```

`limits` deriva de los pool sizes de `hix.json` — cada conexión ocupa
un worker, así que estos son los techos reales por protocolo.

### Layout de la vista

Orden de cajas en la pestaña Run:

1. **Top tiles** — Uptime · Requests · Memory · Sent (4 tiles).
   Eliminada la tile `Active` que era redundante con la caja
   Connections/Workers.
2. **Connections / Workers** — 3 tiles HTTP/WS/SSE con formato
   `now/limit`, coloreadas según utilización (verde <70%, warn 70-90%,
   err >90%).
3. **HTTP** — Request → Total / Avg / Max. Max se pinta `val-warn` si
   supera 1000 ms.
4. **WebSockets** — Recv → Total (frames procesados) / Avg / Max.
5. **SSE** — Stream → Total (streams cerrados) / Avg / Max.
6. **Incoming — req/s** — sparkline existente.

Cajas eliminadas:
- Timing AVG y Timing MAX compuestos (redundantes con las cajas
  por protocolo).
- Panel Connections inferior (contenido migrado a la caja superior).
- Indicador `auto 1s` del header.

Helper JS `msDur(ms)` convierte automáticamente valores > 1000 ms a
segundos/minutos/horas.

## `/job-test` — mejoras de UX

- **Botones Start / Stop movidos al bottom nav** con estilo `btn-dark
  rounded-0 py-2 w-25`, en línea con el módulo Server. La barra
  superior queda solo con el multiplier + estimate.
- **Fila de controles single-line** — `d-flex flex-nowrap` con label
  compacto e input de `5rem`. Ya no se rompe a 2 líneas en móvil.
- **Numeración eliminada** del listado de fases (`1. `, `2. `…), del
  label del progress (`#0 `) y del terminal log (`#N`). El log queda
  más limpio; el estado de la fase (`running` / `done` / `finished`)
  y el tiempo son suficientes.
- El controller sigue siendo `api_sse_job.prg` sin cambios — solo
  ajustes de vista.

## `/ws-test` — feedback sonoro por frame

`views/wstest.html` añade `tick()` (1760 Hz, envelope 80 ms) que se
dispara en cada `ws.onmessage`. Sirve para percibir la cadencia real
de mensajes cuando se está estresando el canal desde la consola.

## Impacto

- `HIX_SUBVERSION_SERVER` sube a `.04`.
- API 100% aditiva:
  - Buckets `STREAM_MS_*` / `WS_MS_*` son nuevos.
  - `HIX_MetricTiming` gana un 3er param opcional con default seguro.
  - `HIX_MetricWsTiming` es un wrapper nuevo.
  - `THixRequest:lWasStream` es DATA nuevo — código existente que
    ignore esta propiedad se comporta idéntico.
- `active_http` / `active_otros` cambian de significado: durante una
  SSE viva, el request ahora suma en OTROS, no en HTTP. Coherente con
  lo que muestra el panel y con el pool que realmente lo sirve.
- No hay cambios en firmas públicas ni retornos existentes.
- Fuera de alcance:
  - **QueryPerformanceCounter helper** para medir sub-ms en Windows.
    Sin él, Avg/Max de handlers triviales quedará en 0. Se dejará
    para cuando aparezca un caso real de benchmarking sub-ms.
  - **Split WS handshake vs frame timing**. Se experimentó y se
    retiró: el server-side handshake es < resolución de reloj (~ms),
    lo que hacía la tile Open siempre 0 y confundía. Los 300 ms que
    ve el cliente son RTT + parseo del navegador, no trabajo del
    servidor.
