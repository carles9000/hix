# HIX v2.1.04

**Date:** 2026-09-11
**Base:** `c4982d3` (2.1.03)

## What was achieved

Isolation of metrics per protocol and complete redesign of the
`/server-info` panel. The motivation was detecting that long SSE streams
were injecting their duration (seconds, even minutes) into `req_ms_avg`,
skewing the HTTP-synchronous average and making a transient spike stick
to the panel for the whole uptime. Separate buckets are created for
stream and WebSocket, and along the way the `active_http` miscount is
fixed when a request switches to streaming mode.

## Changes in the library

### 1. Separate metric buckets

`src/include/hix_const.ch` adds:

```harbour
#define HIXM_STREAM_MS_MAX      "stream_ms_max"
#define HIXM_STREAM_MS_AVG      "stream_ms_avg"
#define HIXM_STREAM_MS_COUNT    "stream_ms_count"
#define HIXM_STREAM_MS_MAX_AT   "stream_ms_max_at"
#define HIXM_STREAM_MS_MAX_PATH "stream_ms_max_path"
#define HIXM_WS_MS_MAX          "ws_ms_max"
#define HIXM_WS_MS_AVG          "ws_ms_avg"
#define HIXM_WS_MS_COUNT        "ws_ms_count"
```

`THixMetrics:Init/Reset` initialize the new counters. `ToJson()` emits
them automatically when iterating over `hCounters`.

### 2. `HIX_MetricTiming( nMs, cPath, lStream )`

Extended signature — the 3rd argument defaults to `.F.` (backward
compatible). When `lStream = .T.`, the update goes to the
`STREAM_MS_*` bucket with its own slowest-path tracker. The rest of the
existing callers require no change.

### 3. `HIX_MetricWsTiming( nMs )` per-frame

New wrapper + `METHOD UpdateWsTiming( nMs )`. It's called inside
`_HixWSFrameLoop` **right after** the `bOnMessage` callback for
TEXT/BINARY frames:

```harbour
CASE nOpcode == WS_OP_TEXT .OR. nOpcode == WS_OP_BINARY
   HIX_Metric( HIXM_BYTES_IN, Len( cPayload ) )
   tFrame := hb_DateTime()
   IF bOnMessage != NIL
      Eval( bOnMessage, oConn, cPayload, nOpcode )
   ENDIF
   HIX_MetricWsTiming( Int( ( hb_DateTime() - tFrame ) * 86400000 ) )
```

**Semantics**: it measures the cost of processing each incoming message,
not the duration of the whole session (which used to pollute `avg` with
minutes). The real cost of a trivial callback (echo) sits below the
resolution of the Windows clock (`hb_DateTime()` ~1-15 ms), so Avg/Max
will show 0 until the handler does real work (DB query, JSON encode,
computation). It's the correct metric — only that sub-ms is
indistinguishable on Windows without QueryPerformanceCounter.

### 4. Counter swap HTTP↔OTROS when entering stream

`THixRequest` gains `DATA lWasStream INIT .F.` (persistent across
keep-alive requests of the same worker). `RespondStart` swaps counters
atomically:

```harbour
IF ! ::lWasStream
   HIX_MetricDec( HIXM_ACTIVE_HTTP  )
   HIX_Metric(    HIXM_ACTIVE_OTROS )
ENDIF
::lStreaming := .T.
::lWasStream := .T.
```

`HIX_WorkerHTTP` receives `lStreamMode` by reference, sets it if
`oReq:lWasStream` after the dispatch, and decrements the correct counter
when exiting the worker. Before: an SSE counted as `active_http` because
the request started as normal HTTP — the panel showed HTTP=1/WS=0/SSE=0
while there was a live stream. Now: HTTP=0/WS=0/SSE=1.

`HIX_MetricTiming` receives `oReq:lWasStream` as 3rd arg, so the stream
time gets registered in `STREAM_MS_*` and not in `REQ_MS_*`.

## Redesign of `/server-info`

Panel fully reorganized in `views/serverinfo.html` +
`controllers/api_serverinfo.prg`.

### JSON exposed by the controller

New keys in the response:

```json
{
  "timing":        { "ms_max", "ms_avg", "count", "max_at", "max_path" },
  "timing_stream": { "ms_max", "ms_avg", "count", "max_at", "max_path" },
  "timing_ws":     { "ms_max", "ms_avg", "count" },
  "limits":        { "http", "ws", "sse", "maxconn" }
}
```

`limits` is derived from the pool sizes in `hix.json` — each connection
occupies a worker, so these are the actual ceilings per protocol.

### View layout

Order of boxes in the Run tab:

1. **Top tiles** — Uptime · Requests · Memory · Sent (4 tiles).
   The `Active` tile was removed as redundant with the
   Connections/Workers box.
2. **Connections / Workers** — 3 HTTP/WS/SSE tiles with `now/limit`
   format, colored by utilization (green <70%, warn 70-90%, err >90%).
3. **HTTP** — Request → Total / Avg / Max. Max is painted `val-warn` if
   it exceeds 1000 ms.
4. **WebSockets** — Recv → Total (frames processed) / Avg / Max.
5. **SSE** — Stream → Total (closed streams) / Avg / Max.
6. **Incoming — req/s** — existing sparkline.

Boxes removed:
- Composite Timing AVG and Timing MAX (redundant with the per-protocol
  boxes).
- Lower Connections panel (content migrated to the top box).
- `auto 1s` indicator from the header.

JS helper `msDur(ms)` automatically converts values > 1000 ms to
seconds/minutes/hours.

## `/job-test` — UX improvements

- **Start / Stop buttons moved to the bottom nav** with `btn-dark
  rounded-0 py-2 w-25` style, in line with the Server module. The top
  bar is left with only the multiplier + estimate.
- **Single-line control row** — `d-flex flex-nowrap` with compact label
  and `5rem` input. No longer wraps to 2 lines on mobile.
- **Numbering removed** from the phase listing (`1. `, `2. `…), from the
  progress label (`#0 `) and from the terminal log (`#N`). The log
  becomes cleaner; phase state (`running` / `done` / `finished`) and
  time are sufficient.
- The controller is still `api_sse_job.prg` unchanged — only view tweaks.

## `/ws-test` — sonic feedback per frame

`views/wstest.html` adds `tick()` (1760 Hz, 80 ms envelope) that fires
on each `ws.onmessage`. It's useful to perceive the actual message
cadence when stressing the channel from the console.

## Impact

- `HIX_SUBVERSION_SERVER` bumps to `.04`.
- 100% additive API:
  - `STREAM_MS_*` / `WS_MS_*` buckets are new.
  - `HIX_MetricTiming` gains an optional 3rd param with a safe default.
  - `HIX_MetricWsTiming` is a new wrapper.
  - `THixRequest:lWasStream` is a new DATA — existing code that ignores
    this property behaves identically.
- `active_http` / `active_otros` change meaning: during a live SSE, the
  request now counts towards OTROS, not HTTP. Consistent with what the
  panel shows and with the pool that actually serves it.
- No changes in public signatures or existing returns.
- Out of scope:
  - **QueryPerformanceCounter helper** to measure sub-ms on Windows.
    Without it, Avg/Max of trivial handlers will stay at 0. It will be
    left for when a real sub-ms benchmarking case shows up.
  - **Split WS handshake vs frame timing**. It was experimented with and
    withdrawn: the server-side handshake is < clock resolution (~ms),
    which made the Open tile always 0 and confusing. The 300 ms the
    client sees are RTT + browser parsing, not server work.
