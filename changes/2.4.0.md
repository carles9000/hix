# HIX v2.4.0

**Date:** 2026-10-13
**Base:** v2.3.12 (unified HIX_Compile* subsystem introduced)
**Plan:** `.claude/plans/2026-10-12_1102 compile_view_migration.md`

## TL;DR

Toda la compilación `.prg`/HRB de la lib — dispatcher, loaders, mw loader,
motor de vistas — habla ahora un único contrato (`HIX_CompileCode` →
hash `{ ok, hrb, err, phase, diagnostics }`). El camino viejo
(`HIX_CompileFile` + `hb_CompileFromBuf` directo) desaparece físicamente
del árbol. Bump semver menor porque se elimina una función pública.

Suite dogfooded del subsistema: **49/49 PASS** en todas las fases.

## Por qué v2.4.0 (y no 2.3.13)

El plan reservaba el bump a minor para el cierre de la migración:

- `HIX_CompileFile` (función pública) eliminada → cambio incompatible
  de API → bump de minor por semver convencional del proyecto.
- `HIX_Compile*` queda consolidada como **la** vía de compilación
  en la lib. Cuatro subsistemas (dispatcher, loaders, mw loader,
  views) convergen al mismo contrato.
- Reorganización física: `src/compile/` como paquete autónomo,
  `src/hix_prepro.prg` desaparecido.

## Qué expone la nueva API

Introducida en v2.3.12, consolidada en v2.4.0:

| Función | Propósito |
|---------|-----------|
| `HIX_CompileCode( cSource [, hOpts] [, cFilename] )` | Compila fuente en memoria → hash normalizado |
| `HIX_CompileCodeFromFile( cPath )` | Wrapper compile-only desde disco (lo que usa el dispatcher) |
| `HIX_CompileRunPrg( cPath [, ...args] )` | Compila + ejecuta + captura runtime en `err`. **Nunca re-raise** |
| `HIX_CompileRunHrb( cHrbBytes [, cVirtualName, ...args] )` | Ejecuta HRB con `HB_HRB_BIND_FORCELOCAL` |
| `HIX_CompileLastError()` | Snapshot runtime del último error — `THREAD STATIC` |
| `HIX_CompileNormalizeErr( hRaw, lRuntime )` | Normaliza snapshot al shape canónico |
| `HIX_CompileFromBuf( ... )` | Low-level buffer compile (uso interno de `HIX_CompileCode`) |
| `HIX_Preamble() / HIX_PreambleLines()` | Preamble público (TRY/CATCH, BLOCK, `?`/`??`, Throw) |
| `HIX_ErrorFromCompileHash( hErr )` | Shim hash→oError para integración con el motor de errores legacy |
| `HIX_ErrorViewFromHash( hErr, nCode, cModule )` | Entry hash-nativa que genera un `oError` de vista con cargo rico |

### Shape de `err` normalizado

- Compile: `{ kind, severity, code, description, file, line, lineCode }`
- Runtime: añade `operation, args, subsystem, genCode, subCode, osCode, filename, stack, aStack`.

## Breaking changes

- **`HIX_CompileFile( cPath )` eliminada.** Sustitutos:
  - Para compile+run: `HIX_CompileRunPrg( cPath )`.
  - Para compile-only (persistir .hrb, usar con `_HixExecWithTimeout`,
    etc.): `HIX_CompileCodeFromFile( cPath )`.
  Ambos devuelven el hash unificado; nunca propagan `Break`.
- **`UGetPPRules()` eliminada.** 0 callers desde la migración a
  preamble-as-text en v15; residuo de mod_harbour.
- **`#XCOMMAND VIEW TO/INTO` eliminada.** Dead code (expandía a
  `UInlinePRG`/`UReplaceBlocks` sin implementación).
- **`oError:operation == "line:N"`** ya no se genera. Nuevo formato
  informativo: `"line N"`. La información oficial de línea vive en
  `oErr:cargo["line"]`.
- **`src/hix_prepro.prg` eliminado.** Las directivas `TRY/CATCH/FINALLY`
  que exponía localmente estaban ya en `src/include/hix_const.ch`.

## No-breaking (compatibilidad preservada)

- `HIX_ErrorView` sigue existiendo con la misma firma. Lo usa cualquier
  error de vista no relacionado con compile (9001 parser, 9004 execute,
  9010/9011 load).
- `HIX_Throw` + `HIX_ErrorFromCompileHash` mantienen el canal oError
  para el worker HTTP; ningún caller externo nota el cambio.
- El `oErr:cargo` de errores de vista contiene las mismas claves
  (`system`, `module`, `process`, `view_code`, `line`, `line_code`,
  `aCode`) + nueva clave `hCompile` cuando la fuente es un hash.

## Mejoras colaterales

- **Boot log enriquecido** — cada fallo de compile en loaders/mw-loader
  se vuelca con descripción + línea + código + snippet, no solo el
  mensaje del `oError`.
- **Motor de vistas** — los diagnósticos de compile cruzan ahora el
  `aLineMap` para recuperar la línea original en el HTML del template,
  no la línea en el `.prg` transpilado intermedio.
- **Stack walker de compile** (`src/compile/frombufex.prg`) deja de
  listar frames de la propia lib — el usuario ve solo su stack.
