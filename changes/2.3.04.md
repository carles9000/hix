# HIX v2.3.04

**Date:** 2026-10-01
**Base:** `2240d63` (2.3.03 Alt A prepared statements binarios — write side)

## What was achieved

Alt A — **SELECT fetch sobre protocolo binario nativo MySQL**. Cierra
el flujo completo: `WDO_MySqlStmtBin` ya cubría INSERT/UPDATE/DELETE +
BLOB streaming en v2.3.03; v2.3.04 añade lectura binaria vía
`mysql_stmt_result_metadata` + `mysql_stmt_store_result` +
`mysql_stmt_bind_result` + `mysql_stmt_fetch` + `mysql_stmt_num_rows` +
`mysql_stmt_free_result`.

Mismo contrato de API que Alt B — `Fetch`, `Fetch_Assoc`, `FetchAll`,
`FCount`, `Count`, `DbStruct` — así que un handler puede intercambiar
`Prepare`/`PrepareBin` sin tocar el resto del código. Cero cambios en
Harbour core: 6 wrappers DynCall nuevos + extensión del `BEGINDUMP`
existente con 5 helpers C de peek sobre buffers de salida.

## API pública nueva

```harbour
oStmt := oConn:PrepareBin( "SELECT id, name, email FROM users WHERE age > ?" )
oStmt:BindParam( 1, 18 )
oStmt:Execute()

oStmt:FCount()               //  número de columnas
oStmt:Count()                //  número de filas (post store_result)
oStmt:DbStruct()             //  array { { cName, cType, nLen, nDec }, ... }

aRow  := oStmt:Fetch()       //  array posicional { v1, v2, v3 } — NIL en NO_DATA
hRow  := oStmt:Fetch_Assoc() //  hash { col => val, ... } — NIL en NO_DATA
aAll  := oStmt:FetchAll( .T. ) //  array completo; .T. = hash por nombre

oStmt:lWeb := .T.            //  activa HIX_HtmlEncode sobre columnas string

oStmt:Close()
```

Guía completa: [`docs/mysql/prepared_statements_bin.md §2.7 + §4.4`](../docs/mysql/prepared_statements_bin.md).

## Diseño

### Store-first + `STMT_ATTR_UPDATE_MAX_LENGTH`

Por defecto MySQL no popula `MYSQL_FIELD.max_length` tras `prepare` —
el campo queda a 0 hasta que el cliente activa el flag
`STMT_ATTR_UPDATE_MAX_LENGTH` y llama `mysql_stmt_store_result`. Sin
ese flag, dimensionar los buffers de salida por `max_length` da buffers
de 1 byte y los strings salen truncados a la primera letra.

Secuencia correcta:

1. `mysql_stmt_execute`
2. `mysql_stmt_result_metadata` → metadata de columnas.
3. `mysql_stmt_attr_set( STMT_ATTR_UPDATE_MAX_LENGTH, &1 )` **antes de**
   `store_result`.
4. `mysql_stmt_store_result` — materializa el resultset entero en
   cliente y rellena `max_length` real por columna.
5. `_RefreshMaxLengths` — re-lee metadata vía `PtrToUI` para capturar
   los nuevos tamaños.
6. `_AllocOutputBuffers` — malloc único de `pDataOut` dimensionado por
   suma de buffers reales + array `MYSQL_BIND` de salida apuntando a
   los slots (`length`, `is_null`, `buffer`, `buffer_length`, `error`).
7. `mysql_stmt_bind_result( pBindOut )` — ata buffers al stmt.
8. `mysql_stmt_fetch` por fila — códigos: 0 OK, 1 ERROR, 100 NO_DATA,
   101 DATA_TRUNCATED (no debería ocurrir tras store-first).

### `MYSQL_BIND` de salida — mismo layout dual

Offsets heredados de v2.3.03 (write side). Los campos
`error` y `error_value` añadidos para v2.3.04 — también difieren por ABI:

| Campo | Windows | Linux |
|---|---:|---:|
| `error` (bool *)      | 24 | 24  |
| `error_value` (bool)  | 88 | 100 |

Smoke test de fetch en el primer SELECT del proceso: `SELECT 42` con
`bind_result` sobre un buffer LONG. Si falla, log loud + `cliente/
Harbour version` — misma estrategia que el smoke de bind_param v2.3.03.

### Decodificación por tipo MySQL

Un único `_WdoDecodeCol` dispatch:

| Tipo MySQL | Lectura | Harbour |
|---|---|---|
| TINY (1), SHORT (2), YEAR (13) | int16 LE | `N` |
| LONG (3), INT24 (9) | int32 LE | `N` |
| LONGLONG (8) | int64 LE | `N` |
| FLOAT (4) | float LE | `N` |
| DOUBLE (5) | double LE | `N` |
| DECIMAL (0), NEWDECIMAL (246), DATE/TIME/DATETIME/TIMESTAMP (10-12,7), STRING variants (253/254), BLOB variants (249-252) | peek bytes `length` | `C` |
| NULL (6) o `is_null`=1 | — | `NIL` |

NUL bytes embebidos preservados — `WDO_BindPeekStr` usa `length` real,
no `strlen`.

### `my_bool` INT+mask — carry forward del fix v2.3.03

`mysql_stmt_bind_result` y `mysql_stmt_free_result` retornan `my_bool`.
Mismo bug Win64: leerlo como `HB_DYN_CTYPE_BOOL` lee basura de los
bytes altos de RAX. Wrappers nuevos usan `HB_DYN_CTYPE_INT + hb_bitAnd
(rc, 0xFF) != 0`. Consistente con `bind_param` / `send_long_data`.

## Notas de diseño

- **Cero cambios en Harbour core.** Condición innegociable del proyecto.
  Los helpers C viven en el `#pragma BEGINDUMP` de
  `wdo_mysql_stmt_bin.prg` — write + read en un único módulo.
- **Store-first vs truncation-fallback.** Dos estrategias posibles:
  (a) buffers fijos + detectar `DATA_TRUNCATED` + re-fetch con buffer
  mayor; (b) `store_result` primero con `UPDATE_MAX_LENGTH`, dimensionar
  por `max_length` real. Elegida (b) — single code path, sin re-fetch,
  menos branching. Trade-off: resultset entero en cliente antes de la
  primera fila — adecuado para los tamaños típicos de respuesta web
  (<1 MB) y consistente con `oConn:Query` que ya se comporta igual.
- **`lWeb` como DATA, no como método.** Permite setear el flag entre
  Execute y Fetch sin modificar la signature de los métodos de lectura.
  Alineado con `WDO_MySqlStmt`.
- **SELECT en Alt A ya no requiere Alt B fallback.** El antipattern 7.1
  de v2.3.03 ("usar Alt A para FetchAll") desaparece. `PrepareBin(cSql,
  .F.)` sigue siendo útil para A/B testing o compatibilidad con drivers
  text-only.
