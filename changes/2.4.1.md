# HIX v2.4.1

**Date:** 2026-10-13
**Base:** v2.4.0
**Type:** Security patch (⚠️ CRITICAL)
**Plan:** `.claude/plans/2026-10-13_1943 config_json_exposure_fix.md`

## TL;DR

**Fuga de secretos.** En modo hixstyle, cualquier fichero en la raíz de
`www/` era servible por HTTP sin filtro. En particular, `GET /config.json`
devolvía el contenido literal del fichero — exponiendo todas las keys
(`jwt`, `csrf`, `session`, `token`, `resource`) a cualquiera que supiese
la URL.

Fix: con la whitelist hixstyle activa (`aAllowDirs != NIL`), **toda**
petición cuya ruta resuelva a un fichero en la raíz de `www/` responde
403. Las únicas rutas válidas pasan por el router (controllers) o por
subdirectorios whitelisteados (`/public/*`).

## Severidad

**Crítica**. Reproducible en producción con una app por defecto:

```
$ curl http://servidor/config.json
{"keys":{"csrf":"...","jwt":"...","session":"...","token":"...","resource":"..."}}
```

Con esas keys un atacante firma JWTs, cookies de sesión, resources
HMAC-firmados — equivale a bypass total de autenticación.

## Causa raíz

`src/hix_dispatcher.prg`, función `_HixCheckACL`:

```harbour
IF aAllowDirs != NIL .AND. ! Empty( cRelDir )
   IF ! _HixWhitelistMatch( aAllowDirs, cRelDir )
      ...403...
   ENDIF
ENDIF
```

Para `/config.json`:
- `SubStr("/config.json", 2) = "config.json"`
- `hb_FNameDir("config.json") = ""` → `cRelDir = ""`
- `! Empty(cRelDir) = .F.` → bloque entero se salta
- El dispatcher continúa, resuelve el fichero físico, lo sirve

El whitelist solo protegía **subdirectorios**. Los ficheros en el root
caían por el hueco.

## Fix

Rama nueva en `_HixCheckACL`:

```harbour
IF aAllowDirs != NIL

   IF Empty( cRelDir )
      lw( "Dispatch: acceso al root bloqueado [" + cPath + "]" )
      HIX_HttpError( oReq, 403 )
      RETURN .F.
   ENDIF

   IF ! _HixWhitelistMatch( aAllowDirs, cRelDir )
      lw( "Dispatch: directorio no en whitelist [" + cPath + "]" )
      HIX_HttpError( oReq, 403 )
      RETURN .F.
   ENDIF

ENDIF
```

Regla simple: en hixstyle, la raíz de `www/` está prohibida — ni ficheros
ni directorios. Rutas válidas son:

- **Controllers** vía router (resueltos antes del dispatcher)
- **Assets** bajo `/public/*` (whitelist explícita)

## Breaking change

Apps hixstyle que servían `www/index.html` sin registrar ruta `/`
**dejan de funcionar** — ahora reciben 403. Migración trivial:

```harbour
oSrv:AddRouteGet( "home", "/", {|| USendView( "home.view.html" ) } )
```

O vía declarativa (`www/routes/web.json`):

```json
{ "name": "home", "url": "/", "action": "controllers/home.prg", "method": "GET" }
```

Apps que servían ficheros extra en el root (manuales PDF, descargas)
deben moverlos a `www/public/` o a un subdirectorio whitelisteado.

## Validación

**Antes del fix** (ejemplo `examples/web/crud`):

```
$ curl -o /dev/null -w "%{http_code}\n" http://localhost:8080/config.json
200
```

**Después del fix**:

```
$ curl -o /dev/null -w "%{http_code}\n" http://localhost:8080/config.json
403
$ curl -o /dev/null -w "%{http_code}\n" http://localhost:8080/index.html
403
$ curl -o /dev/null -w "%{http_code}\n" http://localhost:8080/
200    # ruta "/" registrada por la app, servida por el router
```
