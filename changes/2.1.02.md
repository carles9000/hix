# HIX v2.1.02

**Date:** 2026-09-08
**Base:** `42c592d` (2.1.01)

## What was achieved

The hole through which a HIX worker could remain a zombie serving an
SSE / long-poll after the browser closed the tab is now closed, and a
declarative `"stream": true` flag is introduced on the route so this kind
of handler is not cut off by the dispatcher's `exec_timeout_ms`.

## Changes

### 1. `USendChunk` / `USendStreamStart` / `USendStreamEnd` propagate bool

The three streaming helpers used to return `NIL` and swallow the write
status. An SSE handler had no way to detect the peer's `close()` without
leaning on the dispatcher's global timeout, so a client that closed the
tab left the thread writing to a dead socket until the TCP kernel
noticed (minutes).

They now return `.T./.F.` propagating the return of
`RespondStart` / `RespondChunk` / `RespondEnd` → `WriteChunk` → `Write`.

Official pattern in the handler:

```harbour
DO WHILE lAlive
   IF ! USendChunk( "data: " + hb_jsonEncode( hMsg ) + hb_eol() + hb_eol() )
      lAlive := .F.
      LOOP
   ENDIF
   hb_idleSleep( 1 )
ENDDO
```

No existing callsite compared the return against `NIL`, so the change is
transparent for previous code (verified with grep).

### 2. Per-route flag `"stream": true`

New optional flag in the route hash, both via JSON and programmatically.
When the route carries it, the router uses
`server.stream_exec_timeout_ms` (default `0` = no limit) instead of the
global `exec_timeout_ms` when invoking the dispatcher. Without this flag,
a 30 s SSE + `exec_timeout_ms=30000` would be cut with 504.

- **JSON**:
  ```json
  { "name": "sse", "url": "/events", "action": "controllers/sse.prg",
    "method": "GET", "stream": true }
  ```
- **Programmatic** (7th parameter of `AddRouteGet/Post/Put/Delete`):
  ```harbour
  oSrv:AddRouteGet( "sse", "/events", bAction, "", "", NIL, .T. )
  ```
- **`HIX_RouteAdd`**: 9th parameter (`lStream`, after `lReplace`).
- **`HIX_RouteList`**: includes the `stream` key for inspection.

The dispatcher (`ExecutePrg` / `ExecuteHrb`) now accepts an optional
`nTimeoutMs`; `NIL` falls back to `::nExecTimeout`, `0` disables the
timeout. `_HixExecWithTimeout` already treated `nMs <= 0` as no limit,
so the propagation is a simple extra parameter.

### 3. New config `server.stream_exec_timeout_ms`

Added in `src/hix_config_data.prg` with default `0` and backfill in
`HIX_ValidConfig`. The `hix.json` of the `hi` example has reverted
`exec_timeout_ms` to `30000` and made `stream_exec_timeout_ms: 0` explicit.

### 4. Example `hi/api_sse_ticker.prg`

Rewritten with the `lAlive` pattern and the route marked `"stream": true`
in `www/routes/web.json`. The controller now releases the worker on the
first failed write — behavior verifiable by closing the tab while the
ticker is running.

## Regression tests

Two new suites registered in `tests/unit/app.hbp` and `app.prg`:

- **`hix_test_usendchunk_propagate.prg`** (Transport group,
  entry `USendChunkPro`) — 9 asserts on the bool propagation, plus a
  wall-clock test (<1 s) that simulates the `lAlive` pattern with a mock
  that toggles to failure mode after N chunks.
- **`hix_test_route_stream.prg`** (Routing group, entry `RouteStream`)
  — 5 asserts: default of the flag (`.F.`), `lStream=.T.` propagated to
  the hash, regression of the 4-arg `HIX_RouteAdd`, dispatcher with
  explicit `nTimeoutMs=300` aborting with 504, dispatcher with
  `nTimeoutMs=0` skipping the short `::nExecTimeout`.

## Documentation

`.claude/rules/hix_bible.md` §2 (Routes), §4 (Chunked streaming) and §11
(SSE) updated with the `stream` flag, the `lAlive` pattern and the notes
about `stream_exec_timeout_ms`.

## Impact

- `HIX_SUBVERSION_SERVER` bumps to `.02`.
- Return change of `USendChunk` / `USendStreamStart` /
  `USendStreamEnd`: `NIL → .T./.F.`. No current calls look at the return;
  derived projects that compared `USendChunk(x) == NIL` (unlikely) would
  now evaluate against a bool.
- No parameter signature changes in existing helpers; the `lStream` flag
  is added as an optional trailing parameter in all variants of
  `AddRoute*` and of `HIX_RouteAdd`.
- Out of scope: `SO_KEEPALIVE` to detect abrupt closures without FIN
  (crash, cable) — separate plan.
