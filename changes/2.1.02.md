# HIX v2.1.02

**Fecha:** 2026-09-08
**Base:** `42c592d` (2.1.01)

## Qué se ha conseguido

Se cierra el agujero por el que un worker HIX podía quedarse zombie
sirviendo un SSE / long-poll después de que el navegador cerrara la
pestaña, y se introduce un flag declarativo `"stream": true` en la ruta
para que este tipo de handler no se corte por el `exec_timeout_ms` del
dispatcher.

## Cambios

### 1. `USendChunk` / `USendStreamStart` / `USendStreamEnd` propagan bool

Los tres helpers de streaming devolvían `NIL` y se tragaban el estado de
la escritura. Un handler SSE no tenía forma de detectar el `close()` del
peer sin apoyarse en el timeout global del dispatcher, así que un cliente
que cerraba la pestaña dejaba el hilo escribiendo a un socket muerto hasta
que el TCP kernel lo notase (minutos).

Ahora los tres devuelven `.T./.F.` propagando el retorno de
`RespondStart` / `RespondChunk` / `RespondEnd` → `WriteChunk` → `Write`.

Patrón oficial en el handler:

```harbour
DO WHILE lAlive
   IF ! USendChunk( "data: " + hb_jsonEncode( hMsg ) + hb_eol() + hb_eol() )
      lAlive := .F.
      LOOP
   ENDIF
   hb_idleSleep( 1 )
ENDDO
```

Ningún callsite existente comparaba el retorno contra `NIL`, así que el
cambio es transparente para código previo (verificado con grep).

### 2. Flag por-ruta `"stream": true`

Nuevo flag opcional en el hash de ruta, tanto por JSON como
programáticamente. Cuando la ruta lo lleva, el router usa
`server.stream_exec_timeout_ms` (default `0` = sin límite) en lugar del
`exec_timeout_ms` global al invocar el dispatcher. Sin este flag, un SSE
de 30 s + `exec_timeout_ms=30000` se cortaría con 504.

- **JSON**:
  ```json
  { "name": "sse", "url": "/events", "action": "controllers/sse.prg",
    "method": "GET", "stream": true }
  ```
- **Programático** (7º parámetro de `AddRouteGet/Post/Put/Delete`):
  ```harbour
  oSrv:AddRouteGet( "sse", "/events", bAction, "", "", NIL, .T. )
  ```
- **`HIX_RouteAdd`**: 9º parámetro (`lStream`, tras `lReplace`).
- **`HIX_RouteList`**: incluye la clave `stream` para inspección.

El dispatcher (`ExecutePrg` / `ExecuteHrb`) acepta ahora un
`nTimeoutMs` opcional; `NIL` cae a `::nExecTimeout`, `0` desactiva el
timeout. `_HixExecWithTimeout` ya trataba `nMs <= 0` como sin límite, así
que la propagación es un simple parámetro extra.

### 3. Nueva config `server.stream_exec_timeout_ms`

Añadida en `src/hix_config_data.prg` con default `0` y backfill en
`HIX_ValidConfig`. El `hix.json` del ejemplo `hi` ha revertido
`exec_timeout_ms` a `30000` y explicita `stream_exec_timeout_ms: 0`.

### 4. Ejemplo `hi/api_sse_ticker.prg`

Reescrito con el patrón `lAlive` y la ruta marcada `"stream": true` en
`www/routes/web.json`. El controller ahora libera el worker en la primera
escritura fallida — comportamiento verificable cerrando la pestaña
mientras el ticker corre.

## Tests de regresión

Dos suites nuevas registradas en `tests/unit/app.hbp` y `app.prg`:

- **`hix_test_usendchunk_propagate.prg`** (grupo Transport,
  entrada `USendChunkPro`) — 9 asserts sobre la propagación bool, más un
  test wall-clock (<1 s) que simula el patrón `lAlive` con un mock que
  bascula a modo fallo tras N chunks.
- **`hix_test_route_stream.prg`** (grupo Routing, entrada `RouteStream`)
  — 5 asserts: default del flag (`.F.`), `lStream=.T.` propagado al
  hash, regresión del 4-arg `HIX_RouteAdd`, dispatcher con
  `nTimeoutMs=300` explícito abortando con 504, dispatcher con
  `nTimeoutMs=0` saltándose el `::nExecTimeout` corto.

## Documentación

`.claude/rules/hix_bible.md` §2 (Rutas), §4 (Streaming chunked) y §11
(SSE) actualizadas con el flag `stream`, el patrón `lAlive` y las notas
sobre `stream_exec_timeout_ms`.

## Impacto

- `HIX_SUBVERSION_SERVER` sube a `.02`.
- Cambio de retorno de `USendChunk` / `USendStreamStart` /
  `USendStreamEnd`: `NIL → .T./.F.`. Sin llamadas actuales que miren el
  retorno; los proyectos derivados que compararan `USendChunk(x) == NIL`
  (improbable) pasarían a evaluar contra bool.
- Sin cambios de firma de parámetros en helpers existentes; el flag
  `lStream` se añade como parámetro opcional al final de todas las
  variantes de `AddRoute*` y de `HIX_RouteAdd`.
- Fuera de alcance: `SO_KEEPALIVE` para detectar cierres abruptos sin FIN
  (crash, cable) — plan separado.
