# HIX v2.4.5

**Date:** 2026-11-03
**Base:** v2.4.4
**Type:** Feature + UX fix

## What was achieved

Nueva API introspectiva `GET /hix-info` que expone en JSON la misma
información que el banner de arranque imprime en pantalla (`ShowInit`).
Y mejora de UX en `/hix-setup` para que un POST contra un admin ya
configurado sea diagnosticable en lugar de redirect silencioso.

### 1. `GET /hix-info` — banner de arranque en JSON

Endpoint nuevo registrado junto a `/hix-status`, gated por
`admin.enabled` + `HIX_AdminCheck`. Devuelve un hash con 5 secciones
que replican línea a línea lo que `ShowInit` pinta en consola:

```json
{
  "versions": { "hix", "harbour", "openssl", "curl", "harupdf", "compiler" },
  "rdd":      { "list", "default" },
  "wdo":      { "loaded", "info" },     // solo si WDO_Loaded() no vacío
  "language": { "name", "codepage", "cdpuni" },
  "server":   { "startup", "app_path", "app_name", "root", "hixstyle_active" }
}
```

Backend: nueva `FUNCTION HIX_InfoHash()` en `hix_server.prg` como
fuente de verdad reutilizable. `ShowInit` no cambia — sigue
construyendo el banner línea a línea.

### 2. UX fix — `POST /hix-setup` cuando admin ya existe

Antes: redirect silencioso a `/hix-login`. Un cliente que intentaba
crear credenciales no se enteraba de que el server ya tenía admin
configurado y veía su password simplemente "no funcionar" en login.

Ahora: `409 Conflict` + mensaje claro:
> *Admin is already configured. Use /hix-login, or clear the admin
> section in hix.json to reset.*

`GET /hix-setup` sigue redirigiendo a `/hix-login` (UX correcta para
navegador). Protección write-once intacta: setup NO sobrescribe
credenciales existentes.
