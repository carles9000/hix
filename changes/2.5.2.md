# HIX v2.5.2

**Date:** 2026-11-22
**Base:** v2.5.1
**Plan:** `.claude/plans/2026-11-21_2300 claim1_sqlite_contract.md`
**Origin:** Claim 1 del informe de revisión externa v2.5.

**Type:** Contract fix — alinear el driver `WDO_Sqlite3` con tres
promesas documentadas que la implementación v2.5.0 incumplía:

1. `Close()` sobre un singleton registrado destruía la conexión.
2. `BindParam(..., "i"|"n"|"s")` enlazaba silenciosamente NULL.
3. `Transaction()` tragaba la descripción del error en `cError`.

## TL;DR

Los ejemplos publicados de la guía SQLite3/SQLCipher ahora funcionan
sin sorpresas:

```harbour
oConn := WDO_Get( "APP" )
oConn:Close()                     // no-op: el singleton sigue vivo
oStmt := oConn:Prepare( "INSERT INTO t ( a, b, c ) VALUES ( ?, ?, ? )" )
oStmt:BindParam( 1, 42,     "i" ) // antes: silent NULL — ahora enlaza 42
oStmt:BindParam( 2, "hi",   "s" ) // antes: silent NULL — ahora enlaza texto
oStmt:BindParam( 3, 3.14,   "n" ) // antes: silent NULL — ahora enlaza 3.14
oStmt:BindParam( 1, 1,      "z" ) // antes: silent NULL — ahora .F. + cError
oStmt:Execute()
oStmt:Free()

oConn:Transaction( {| o | o:Exec( "..." ), _Raise() } )
// → .F.   y   oConn:cError contiene la descripción original
```

## Cambios

### `src/wdo/sqlite3/wdo_sqlite3.prg`

- Nueva `DATA lStandalone INIT .F.`. La pone a `.T.`
  `WDO_RegisterConn` al registrar la instancia en el store de
  singletons.
- `METHOD Close()` retorna temprano si `::lStandalone == .T.` — no
  cierra `pDb`, no libera la DLL, no toca `lConnect`. El dispatcher
  no cerraba nunca el singleton (no está en `_Borrowed()`); el bug
  era puramente user-code siguiendo el ejemplo publicado.
- `METHOD Transaction()` — el `CATCH` ahora llama `::SetError(_(
  'WDO_ERR_SQLITE_TRANSACTION_ABORT', oErr:description ))` **antes**
  de `Rollback()`, dejando la descripción original en `::cError`.
  Se emite además un `lw()` con el motivo para los logs.

### `src/wdo/sqlite3/wdo_sqlite3_stmt.prg`

- `METHOD BindParam` normaliza `Upper( AllTrim( cType ) )` y mapea
  los alias documentados `s → T`, `n → D` **antes** del DO CASE
  final.
- La rama `OTHERWISE` ya no cae a `SqliteBindNull`: setea
  `::lError`, propaga `::cError` vía `::oConn:SetError(...)` y
  retorna `.F.` con una descripción explícita `"unknown type 'z'"`.
- `cType == "D"` ahora enlaza como texto numérico (`hb_NToS`) y
  deja que la afinidad de columna (REAL / NUMERIC) convierta en
  SQLite. Motivo: `hb_DynCall` de Harbour **no soporta doubles en
  XMM registers** sobre Windows x64 — pasa el `HB_DYN_CTYPE_DOUBLE`
  como dos `HB_U32` en registros enteros, así que
  `sqlite3_bind_double` recibía basura y el valor almacenado salía
  `0.0`. Documentado inline en el método.

### `src/wdo/wdo_pool.prg`

- `WDO_RegisterConn` → activa `::lStandalone := .T.` tras registrar
  la instancia (con `__objHasMsg` guard, el flag solo existe en
  `WDO_Sqlite3`).
- `WDO_UnregisterConn` → desactiva el flag justo antes del
  `oConn:Close()`, de modo que el Close *real* se ejecuta y libera
  `pDb` + DLL.

### `src/lang/hix_lang.prg`

- Nueva clave `WDO_ERR_SQLITE_TRANSACTION_ABORT = "SQLite3
  Transaction aborted: {1}"` para la descripción canónica del
  error en `cError` tras un rollback.

### Tests

- `tests/unit/src/hix_test_sqlite3_contract.prg` — nuevo grupo
  `Sqlite3Contract` (16 asserts), registrado en `app.hbp` + `app.prg`.
  Cubre los tres contratos:
  - **T01–T06**: `Close()` no-op sobre singleton registrado +
    `WDO_Get` posterior sigue devolviendo conexión usable;
    `WDO_UnregisterConn` sí ejecuta el Close real (`lConnect=.F.`,
    `pDb=NIL`).
  - **T07–T11**: `BindParam` acepta alias `i/s/n` (round-trip
    numérico, string y decimal); tipo desconocido devuelve `.F.` +
    `cError` no vacío.
  - **T12–T16**: `Transaction()` rollback preserva `cError`
    con la descripción original y revierte filas; commit en el
    camino feliz persiste filas.
- Suite completa: **2348 total | 2348 passed | 0 failed**.

## Migración desde v2.5.0/v2.5.1

**Ninguna acción requerida**. Los cambios son estrictamente
retrocompatibles para código que ya seguía el contrato
documentado. El único "efecto visible" nuevo es que:

- `Close()` sobre singletons deja de destruir la BD (código que
  dependía del bug anterior nunca debería haber existido).
- `BindParam(..., "i"|"n"|"s")` antes almacenaba NULL; ahora
  almacena el valor correcto. Aplicaciones afectadas por el bug
  silencioso empezarán a ver valores en vez de NULL.

## Fuera de scope

- `sqlite3_bind_double` nativo (requeriría una contribución a
  `hbdyn.c` para pasar doubles en XMM0..XMM3 en x64 Win). El
  workaround via `bind_text` + afinidad de columna es correcto
  para todos los tipos SQLite estándar.
