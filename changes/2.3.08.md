# HIX v2.3.08

**Date:** 2026-10-04
**Base:** v2.3.07 (dispatcher release hook)

## What was achieved

Fix de leak permanente del pool MySQL cuando el dispatcher tenía que matar
hilos hijos por `exec_timeout_ms` + nuevos tuning knobs expuestos en
`config.json`.

- **Fix: MySQL connection leak under dispatcher timeout** —
  `_HixExecWithTimeout` (`src/hix_dispatcher.prg`) ejecuta cada controller
  en un hilo hijo cuando `exec_timeout_ms > 0`. Si el controller está
  bloqueado dentro de `mysql_real_query → recv()` cuando salta el timeout,
  `hb_threadDetach` deja al hijo vivo con el socket colgado, el FINALLY de
  `_HixRunHrb` nunca corre, y el slot del pool queda `busy = .T.` para
  siempre. Bajo carga sostenida el pool se vacía por completo (observado
  en producción: 32 slots perdidos en 28 s, luego 4 h sin recuperarse).
  Fix: `WDO_MySql:Open()` ahora llama `mysql_options()` con
  `MYSQL_OPT_READ_TIMEOUT`, `MYSQL_OPT_WRITE_TIMEOUT` y
  `MYSQL_OPT_CONNECT_TIMEOUT` antes de `mysql_real_connect`. Cuando el
  hilo hijo queda bloqueado en `recv()`, el socket timeout fuerza error en
  pocos segundos → el FINALLY propaga → la conexión vuelve al pool.

- **Nuevas claves `read_timeout_s` + `connect_timeout_s`** en
  `databases.<pool>.*` de `www/config.json`. Defaults 30 s y 10 s. Deben
  ser mayores que la query legítima más lenta y acordes con el
  `exec_timeout_ms` del dispatcher.

- **Nueva clave `debug` en `databases.<pool>.*`** — si cualquier pool
  tiene `"debug": true`, `HIX_InitPoolsFromConfig` llama `HIX_DbgReset()`
  y `HIX_DbgEnable(.T.)`. `dbg.log` se vacía al arrancar y captura
  Acquire/Release del pool y toda `HIX_Dbg()` instrumentada. Útil para
  diagnóstico sin tocar código.

- **Hi: bench UI corregido** — `pool_size` del ejemplo subido a 20 (= tope
  del bench). Input "Concurrency" con `max=20` duro: listener `input`
  recorta al vuelo valores superiores, listener `blur` normaliza < 1 o
  vacíos → 1. Default UI = 5 (conservador). Combinado con el clamp JS en
  `startBench()` da triple barrera. `debug=true` por defecto para que la
  demo imprima trazas en `dbg.log`.

- **site-docs WDO MySQL (es/en/it)** — tabla "Campos disponibles" en
  `config.md` ampliada con `read_timeout_s`, `connect_timeout_s`, `debug`
  y nota `!!! warning` sobre la relación con `exec_timeout_ms`.

## Notes

- `read_timeout_s` default 30 s está pensado para `exec_timeout_ms = 30000`
  (default del dispatcher). Si el usuario sube uno, debe subir el otro.
- `debug: true` NO es para producción — tiene coste de I/O en cada
  Acquire/Release y pollea `dbg.log` desde el worker.
- El fix se verificó con bench 1000 req × 20 concurrentes contra la demo
  Hi: 1000/1000 OK, 0 errores de pool.
