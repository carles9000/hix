## Feature 2 — `WDO_DefaultErrorHandler`

Hasta 2.3.01 cada proyecto que quería usar el pool WDO se copiaba
`WdoErrorHandler` del ejemplo (`examples/wdo/src/app.prg`) para poder
poner `"berror": "WdoErrorHandler"` en su `www/config.json`. Fricción
innecesaria — el 95% de los proyectos sólo necesitan log + `USendError(500)`.

2.3.02 extrae ese handler a la lib como `WDO_DefaultErrorHandler`:

```json
{
  "databases": {
    "mysql": { ..., "berror": "WDO_DefaultErrorHandler" }
  }
}
```

Implementación (`src/wdo/wdo_error_handler_default.prg`):

```harbour
FUNCTION WDO_DefaultErrorHandler( oErr, oConn )
   HB_SYMBOL_UNUSED( oConn )
   le( "[WDO] " + oErr:description + " @ " + oErr:operation )
   IF HIX_GetRequest() != NIL
      USendError( 500, "DB error: " + oErr:description )
   ENDIF
RETU NIL
```

Prefijo `WDO_` consistente con el resto de la API pública (`WDO_Get`,
`WDO_InitPoolMySql`, `WDO_PoolStats`, `WDO_ListPools`). No colisiona
con el `WdoErrorHandler` de `examples/wdo/`, que queda como plantilla
para handlers custom (Slack alert, retry, Sentry, WDO metrics tagging,
etc.).

Cero breaking changes — los proyectos existentes con
`"berror": "WdoErrorHandler"` siguen funcionando sin cambios.

## Feature 1 — opt-in WDO metrics registry

Un módulo de métricas paralelo a `HIX_Metric*` pero focalizado en el
subsistema WDO. Cubre el hueco identificado en `docs/mysql/pendientes.md
§3` (métricas Prometheus / dashboard) por la parte de captura — el
export a Prometheus queda en cola, pero los contadores ya están.

Activación en `www/config.json`:

```json
{ "sets": { "wdo_metrics": true, "wdo_metrics_top_n": 10 } }
```

Sin esta clave, todas las llamadas `WDO_Metric*` colapsan al fast-path
`IF soMetrics == NIL ; RETU`, sin overhead medible. Con la clave, cada
query / acquire / release paga 1 mutex lock + escritura en hash.

### Instrumentación

| Punto | Métrica |
|---|---|
| `WDO_MySql:Query`     | pre/post timing → `queries_total`, `queries_<type>`, `queries_by_pool_<key>`, `query_ms_*`, top-N |
| `WDO_MySql:Query` err | `queries_errors` |
| `WDO_MySql:Prepare`   | igual (type = `prepare`) |
| `WDO_MySqlStmt:Execute` | agregado 1-por-Execute (SET internos no duplican timing) |
| `WDO_Pool:Acquire`    | `acquires_total`, `acquires_timeout`, `active_conn`, `acquire_ms_*` |
| `WDO_Pool:Release`    | `releases_total`, `active_conn--` |
| `WDO_ReleaseAllThread`| `releases_reclaimed += <n>` tras el log de leak |

### Clasificación SQL

`_WdoSqlType` mira el primer token significativo, tolerante a
comentarios `--` y `/* */` iniciales. Buckets: `select/insert/update/
delete/prepare/execute/other`. `WITH …` (CTE) clasifica como `select`.

### Origen de la query

`_WdoSourceFromStack` recorre `ProcName(2..20)` filtrando frames del
propio WDO (`WDO_*`, `_HIXWDO_*`, `_WDO*`, `*_METRIC*`, y métodos
de clase `WDO_MYSQL:`, `WDO_MYSQLSTMT:`, `WDO_POOL:`). Reporta
`"FUNC:LINE"` del primer frame ajeno. Si el llamante pasa `cSource`
explícito, se respeta.

### `cPoolKey` en la conexión

`WDO_MySql` gana `DATA cPoolKey INIT "-"`. El factory
`_WdoMySqlPoolNew` lo inicializa a `Lower(cKey)` para que cada
métrica reporte el pool origen. Conexiones fuera de pool quedan como
`"-"`.

### Top-N slowest

Array desc por `ms`, cap configurable (default 10). Cada entrada:
`{ ms, at, sql, source, pool, type }`. SQL recortado a 200 chars con
whitespace colapsado.

### Running avg

Fórmula incremental `avg += (nMs - avg) / count`, redondeada a 2
decimales. Evita mantener total acumulado y funciona para uptime largo
sin overflow.

### Integración con `HIX_MetricsJson`

Cuando el módulo está activo, `HIX_MetricsJson()` inyecta el bloque
`wdo` antes del `}` final. Un endpoint `/metrics` que ya sirve
`HIX_MetricsJson` publica el WDO sin cambios.

### Bootstrap / teardown

`src/hix_server.prg → _HixStartWdoMetrics` (STATIC) lee
`HIX_ConfigApp("sets") → wdo_metrics`, y si es `.T.` llama
`WDO_MetricsSetTopN(nTopN)` + `WDO_MetricsInit()`. Se invoca justo
después de `HIX_MetricsInit()` con `lOwnsGlobals=.T.`. Teardown
simétrico: `WDO_MetricsClose()` antes de `HIX_MetricsClose()` en
los dos sitios donde el server cierra.

## Notas de diseño

- **Fast-path opt-in**. Copiado del patrón `HIX_Dbg` (memory
  `project_hix_dbg_hot_path.md`): trazas en hot path sin gate hunden
  el rendimiento. `WDO_Metric*` siempre bailan primero si
  `soMetrics == NIL`.
- **No duplicar timing en Execute**. Las llamadas `SET @pN` internas
  del `Execute()` van vía `::oConn:mysql_query(...)` (raw DynCall),
  no vía `::oConn:Query(...)`. Por eso `Execute` reporta 1 sola
  entrada `type=execute` en lugar de N+1 (N SET + 1 EXECUTE).
- **Running avg**. La fórmula incremental es exacta para stream
  uniforme y solo diverge levemente del true mean con distribuciones
  muy sesgadas. Suficiente para monitoring — para percentiles reales
  hace falta histograma (pendiente §3).
- **`hb_JsonEncode` para ToJson**. Blindaje contra SQL con quotes,
  backslashes o unicode que rompería un ensamblador string manual.
