## What was achieved

**Fix: `bError` no longer leaks across pool acquisitions.**

En 2.2.04 se introdujo `WDO_InitPoolMySql(..., bError)` para que cada
conexión del pool tenga un handler de errores app-wide. Un handler podía
sobreescribirlo por request:

```harbour
oConn := WDO_Get( "MYSQL" )
oConn:bError := {|| NIL }
oConn:Query( ... )
oConn:Close()
```

Pero `Close()` liberaba el slot sin restaurar el `bError` original. La
siguiente request que agarrase ese mismo slot heredaba el `{|| NIL }`
y el handler pool-wide quedaba silenciado a perpetuidad para ese slot.
El workaround documentado era guardar y restaurar a mano — feo y
propenso a fugas por excepciones.

Ahora `WDO_Pool` guarda el `bError` inyectado por el factory en la
propia estructura del slot (5ª columna de `aItems`) y `Release` lo
restaura antes de marcar la conexión libre. El path de reconexión
dentro de `Acquire` (cuando el ping falla y se re-abre la conexión)
también re-inyecta el snapshot, manteniendo el invariante:

> Toda conexión devuelta por `WDO_Get` tiene el `bError` pool-wide.

## Changes

- `src/wdo/wdo_pool.prg`:
  - `Init()`: snapshot `oConn:bError` en `aItems[i][5]` tras el factory.
  - `Release()`: restaura `oConn:bError` desde el slot antes de liberar.
  - `Acquire()`: re-inyecta `bError` tras un reconnect (ping fallido).
- `tests/wdo/test_wdo_mysql.prg`: `TestPoolBError` gana un 7º assert
  que verifica la no-persistencia del override tras `Close`.
- `docs/mysql/instance_vs_pool.md` §10: elimina el aviso del footgun
  y el patrón save/restore; documenta el auto-restore.
- `docs/mysql/instance_vs_pool.md` §11: actualiza referencia obsoleta
  al test antiguo → `tests/wdo/test_wdo_mysql`.
