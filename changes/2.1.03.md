# HIX v2.1.03

**Date:** 2026-09-09
**Base:** `955e59b` (2.1.02)

## What was achieved

The second hole in the SSE cycle is closed: in v2.1.02 the `lAlive`
pattern leaning on the return of `USendChunk` was **enough for aggressive
`RST` but not for the browser's clean `FIN`** — Windows leaves the 4 bytes
of an SSE probe (`":k\r\n\r\n"`) in the local TCP buffer and `send()`
returns OK, so a `Ctrl+F5` on `/sse-test` was accumulating users in
`sse_liveroom_users` because the old worker was still alive while the
new one had already incremented the counter.

The solution is to do a **`recv MSG_PEEK` with timeout 0** on the same
socket before each probe. It's a non-destructive operation that detects
the peer's `FIN` in the same 300 ms tick, without depending on the TCP
buffer or the kernel keepalive (whose first probe on Windows is by
default ~2 h — useless for SSE).

## Changes

### 1. New `METHOD PeerAlive()` in `THixIO`

Added in `src/hix_io.prg`. It does `hb_socketRecv(..., 1, HB_SOCKET_MSG_PEEK, 0)`
on the TCP socket and classifies the return:

| `hb_socketRecv` | State                                       |
|-----------------|---------------------------------------------|
| `0`             | Peer sent FIN → `.F.`                       |
| `> 0`           | Peekable data → `.T.`                       |
| `-1` + fatal    | CONNRESET/CONNABORTED/NOTCONN/PIPE/SHUTDOWN → `.F.` |
| `-1` + other    | WOULDBLOCK/AGAIN/etc. → `.T.`               |

On SSL sessions it degrades to `.T.` (the TCP peek does not see the
decrypted stream bytes). It's a known limitation — for HTTPS SSE we
still rely on the return of `USendChunk` with `hb_idleSleep(0.3)`.

Internal helper `_HixIsFatalSocketError( nErr )` centralizes the
classification of socket error codes.

### 2. Wrapper `METHOD PeerAlive() INLINE ::oIO:PeerAlive()` in `THixRequest`

Added in `src/hix_request.prg` with a NIL-guard on `::oIO`. A request
without an IO channel (mocks, aborted request, etc.) returns `.F.`.

### 3. New helper `UPeerAlive()` in `hix_helpers.prg`

Delegates to `HIX_GetRequest():PeerAlive()`. Returns `.F.` if there is no
active request in the thread. Canonical usage in stream handlers:

```harbour
DO WHILE lAlive
   IF ! UPeerAlive()           // primary exit: FIN detected in the same tick
      lAlive := .F.
      LOOP
   ENDIF
   IF ! USendChunk( ... )      // secondary: aggressive RST
      lAlive := .F.
      LOOP
   ENDIF
   ...
ENDDO
```

### 4. Example `examples/web/hi/www/controllers/api_sse_ticker.prg`

Rewritten with `UPeerAlive()` as primary exit + `USendChunk` as safety
net. Sleep in 300 ms slices with peek between each one, so a close
during the wait is noticed in <1 s without depending on `send()`.

## Regression test

`tests/unit/src/hix_test_peer_alive.prg` (Transport group, entry
`PeerAlive`) — 6 asserts:

1. `UPeerAlive()` with no active request → `.F.`
2. `UPeerAlive()` with request but without `oIO` → `.F.`
3. `UPeerAlive()` with alive IO → `.T.`
4. `UPeerAlive()` with dead IO → `.F.`
5. `lAlive` loop exits after 3 ticks when the peer dies.
6. `THixIO:PeerAlive()` with `hSocket` NIL → `.F.` (guard).

Full suite: **1745 total | 1745 passed | 0 failed** (58 groups).

## Additional fix — SSE detector race

With `UPeerAlive()` already working, a second symptom appeared: the 2nd
consecutive Start of a long-job SSE hung (Chrome fires `onopen`, no
chunk arrives, `dbg.log` and `access.log` show no trace of the request).

**Cause**: `HIX_DetectProtocol` in `src/hix_socket.prg` classified as
legacy pub/sub SSE any peek containing `text/event-stream`, and the
accept loop dispatches directly to `oPoolOtros` (legacy worker
`_HixWorkerSSE`) without going through the router. The peek is a race:

- Runs that lose it (peek catches only `GET /...\r\n`): fall through to
  `HIX_CONN_HTTP` → router → controller. OK.
- Runs that win it (packet with full headers, typical after a socket
  reopen with Happy Eyeballs IPv4 fallback): dispatch to the legacy
  worker → 124 bytes of hardcoded headers + keep-alive loop of the bus
  by channel. The controller is never invoked.

**Fix**: removed the `IF HIX_TOKEN_SSE_ACCEPT $ cLower ...` line from
`HIX_DetectProtocol`. In v2.x all SSE goes through a route with
`stream: true`; Accept-header detection was residual from v1 and only
reintroduced the race. LongPoll keeps its detection.

**API impact**: zero. Routes already declared with `stream: true` keep
working identically; what changes is that they now **always** reach the
router (before it was intermittent).

## Impact

- `HIX_SUBVERSION_SERVER` bumps to `.03`.
- 100% additive API: `PeerAlive` in `THixIO`/`THixRequest` + the
  `UPeerAlive` helper are new. Nothing existing changes signature or return.
- SSE detector: internal change not observable by routes correctly
  declared with `stream: true`. It does break any legacy usage that
  depended on the Accept-header dispatch towards `_HixWorkerSSE`
  (pub/sub by channel with no route). No example in the repo depends on that.
- SSL: `PeerAlive()` returns `.T.` (degraded). Documented.
- Out of scope:
  - **SSL/TLS peek**: requires BIO peek or storing the decrypted byte
    separately. Separate plan (`plan_ssl_peer_alive.md` — future).
  - **Tuning `WSAIoctl SIO_KEEPALIVE_VALS`** to shorten the first
    keepalive probe on Windows (2 h → 30 s).
  - **`AddRouteWs` to unify WS under the router**. Idea documented in
    `.claude/plans/2026-09-11_0910 v3_addroutews_unified_router.md`.
